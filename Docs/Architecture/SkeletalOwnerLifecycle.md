# 骨格runtimeの実owner lifecycleとM9 consumer

## 実経路と所有

ApplicationProcessorが実際に駆動するCore::Engine::GEngine（Engine pointer）と、Registryを持つCore::GEngine（NorvesEngine）は別である。NorvesEngineの通常メンバSkeletalAssetSessionを、実ApplicationProcessorのInitialize・Tick・Shutdownから明示駆動する。NorvesEngine::Initialize/Update/Shutdownや別rendererを丸ごと呼ばない。

BeginはJobs/Engine作成後、handler初期化より前。明示ownerを固定し、未初期化で空のRegistryだけ取得責任を持ってInitializeする。既に初期化済みなら借用し、そのGC/Shutdownを奪わない。未初期化なのに既存登録がある場合はID resetを避けて拒否する。未登録候補や旧handleをsession外から持ち越さないのはcaller条件である。

取得receiptは準備確保より先に記録し、失敗時は取得したRegistryだけを戻す。runtimeはBeginごとに新しいinstanceで、Close後のBind再利用はしない。最初のsnapshot BindまではFlushが正常no-opなので、通常Rendering3DTestの起動選択を変えない。

## owner Tick、pause、終了

実TickはTickSkeletalOwnerAssetsAndHandlerを使い、最大4 groupのFlush→handler.OnUpdateをsimulation gateの外側で行う。4はgroup予算でありcallback数/時間上限ではない。取得Registryだけを同ownerでGCする。Pause中もdelegate配送は進むが、M9のWorld attachはGameMode Tick再開まで待つ。

終了は入力/描画/consumerを壊す前に骨格Close→Drainを行う。骨格workerはCPUのみでrendererを待たないため、既存RenderWorld quiesceより前にこのhandoff境界を閉じられる。callback内のDeferredならRequestExitだけを残して戻り、owner Tickも残りhandler/World/描画更新を進めない。外側Run終了後のShutdownでDrainedを確認してから既存の入力解除、render quiesce、Jobs停止、mode Leave、World/Script/RHI/handler解体を行う。

Endは全consumer/renderer解体後、Engine/Jobs破棄前。取得RegistryだけShutdownし、借用Registryのepoch/slots/外部参照を保持する。再Initializeは新runtime/domainと新consumer stateを使う。ResourceHandleはRegistry session epochを含まないため、旧typed handleの任意session越し無効性を保証せず、終了時にconsumerのhandle/strong参照を捨てる。

## M9のeventと明示clip

OnPostInitializeのPrepareM9WorldAssetsは既存audio2本のcook読込を保持し、骨格だけruntime.LoadAsyncへ置換する。CreateTransientによる逐次登録やClips[0]取り出しを残さない。既定入力はModels/M9Skinned/ValidU8Float.gltfとWaveで、loaderの固定pathにはしない。

M9SkeletalPreparationは要求ごとに新しい所有stateを作り、callbackはweakだけを捕捉する。取消時は古いstateを失効させる。成功aggregateと名前で選んだclip、または型付き失敗を一回eventへ置く。TakeEventは一度だけで、未着時はoutを変えない。ID0拒否に存在しないcallbackを待たない。

EnterはPendingを失敗にしない。routine Tickが配送済みeventを一度consumeし、実AttachM9SkeletalAsset(World,Scope,asset,clip,...)でEntity/componentを一回生成する。出力済みobject/componentがある二重attachは拒否する。componentは同aggregateのLoaded/Validなclipだけ明示選択する。選択失敗は旧設定を保持し、membership喪失時は描画を拒否する。未指定時だけ動的な旧先頭別名を使い、既存の同aggregate.SetResources差し替え互換を保つ。

M9のcapture/audio tick数はattach後から進める。failed Enter guardとLeave cleanupは準備eventを先に取消・失効し、input/audio/asset解放へ続く。初期化前・イベント前の失敗でもhandler.OnShutdownが借用runtimeへの取消先を解放する。callback自体ではWorld/audio/一時GameModeContextを触らない。同じM9 smokeへ再Enterする場合は新しいPrepare要求が必要であり、消費済みeventを再attachしない。CanPrepareは消費済みactivationをCancelまで拒否し、Game handlerはaudio/config変更前にこのgateを使う。CanEnterはpending要求または未消費eventだけを許可し、無準備・取消済み・消費済みでのEnterはfailure guard経由で失敗する。

## snapshotとasset-settle

M9のみがaccepted immutable snapshotをsessionへBindする。骨格snapshot pin中は、Gameの別snapshot reloadをrenderer更新前にskeletal_snapshot_pinnedとして拒否する。Texture/Model/Skeletalの3者transactionへ拡大しない。通常起動で骨格未bindなら従来のreloadを保つ。

asset-settleは従来renderer pendingにruntime pendingとhandlerの未consume eventを加える。Flush前にもpendingを観測し、即完了が最初のTickでconsumeされても観測を失わない。Pause中の未attach eventでsettleを早抜けしない。

## 検証境界

CPU試験は実session/owner helper、M9準備helper、World/Scopeの実attach、SkinnedMeshComponentの明示clipを使う。所有/借用Registry、準備例外、pause配送、複数session、取消、typed failure、Deferred、clip差し替えと既存先頭互換を常時CHECKでDebug/Release検証する。

Pythonの8 source契約と既存M9 ContractOnlyは実App/handler/routineへの配線位置・順序を検査する。Game Debug/Releaseをcompileしhashを記録するが、Gameの起動・GPU描画・XAudio2再生ではない。Windows native実行はCPU helperに限る。M9のt0/t1・negative control・音声drain・既定Rendering3DTest撮影・実犬/Blender品質は未検証として残す。境界注入は実allocator全域OOMの証明ではない。
