# 荒野の雲を Cycles の体積で描く仕組み

荒野の雲の正解の絵（SCN-WLR-CLOUD-REF）のために、雲の書き出し（`WastelandCloudDump.md` の入力の契約）を Blender の体積として
読み込み、同じ太陽・空・カメラで Cycles に描いて、書き出しの視線ごとにエンジンと比べる仕組みの記録。
判定日: 2026-10-22。ブランチ `feature/scene-launcher`。タスク SCN-WLR-CLOUD-REF-BLENDER。エンジンの描画は変えていない。

## 道具

| 何 | どこ | 何をするか |
|---|---|---|
| `BlenderReference.py --cloud` | `Scripts/Terrain/BlenderReference.py` | 書き出しから密度の格子を焼いて OpenVDB の体積として置き、空だけの画・透過率の画・本描画（種 A・B）を描く。`--trial` は 1 本 64 サンプル |
| `CloudVolume.py` | `Scripts/Terrain/` | 格子の範囲と焼き方、カメラの向き、視線の領域、収束の測り方（Blender の中と照合で共有。numpy だけ） |
| `ReferenceCheck.py --cloud` | `Scripts/Terrain/CloudCheck.py` | 比較が成り立つ条件を検査し、視線ごと・領域ごとの表と量を作る。報告は `<Cycles の書き先>/cloud_check.json`、見比べの画は `cloud_<視点>.png` |

使い方（試しの描画）:

```
python Scripts/Terrain/BlenderReference.py --cloud --capture .harness/runs/scene-capture/SCN-WLR-CLOUD-REF-DUMP --trial --out .harness/runs/scene-capture/SCN-WLR-CLOUD-REF-BLENDER
python Scripts/Terrain/ReferenceCheck.py --cloud --engine .harness/runs/scene-capture/SCN-WLR-CLOUD-REF-DUMP --reference .harness/runs/scene-capture/SCN-WLR-CLOUD-REF-BLENDER --trial --verify
```

## Blender の場面

- **座標**: カメラの真下の惑星の表面を原点とするエンジンの向きの座標（雲の枠）を、Blender の座標へ `x = X、y = −Z、z = Y` で移す。
  カメラは高さ max(カメラの y, 1)（雲の式の高度の下限。cloud_sky では 1 m）、惑星の中心は 惑星の半径だけ下。
- **密度**: `CloudDumpCheck.CloudModel.density`（エンジンの `SampleCloudDensity` の写し）を、カメラの水平の右・前と上を軸とする
  16 m の格子の点で評価する。範囲は画面の縁の視線が雲の層の底と頂の球殻と交わる点の水平の外接箱を 2 km 広げた箱
  （cloud_sky で 28.5 × 16.7 km、高さは雲の層 2500〜3600 m に地球の丸みの分を足す）で、1785 × 1045 × 74 点、密度のある点 3361 万。
  細部で縁を削るのはカメラから 18 km 以内の点（エンジンの視線と同じ）。焼くのに約 180 秒。
  格子の大きさは、書き出しの視線で式を 4 m ごとに積んだ透過率との差で選んだ（8 m で最大 0.0013、12 m で 0.0026、16 m で 0.004）。
- **材質**: 散乱の係数 = 格子の値 × 消散係数 0.006 /m、吸収 0（エンジンの積分は散乱のアルベド 1）。位相関数はエンジンの最初の回の
  mix(HG(0.8), HG(−0.3), 0.3) を、異方性 0.8 と −0.3 の Volume Scatter（色は白。既定の 0.8 のままだと散乱が 2 割減る）を
  係数 0.7 と 0.3 で足して作る。多重散乱はエンジンの近似（3 回の和）でなく Cycles が光路で数える（体積の跳ね返り 256 回まで）。
  格子の値 0.001 以下は空（`clipping`。エンジンも密度 0.001 以下の歩を飛ばす）。
- **太陽**: 書き出しの太陽の地表の照度（RGB の lux）を照度とする Sun（色 = RGB ÷ 最大、強さ = 最大）、角の直径はエンジンの太陽の円盤と同じ。
- **空**: 空の放射輝度 LUT をそのまま画像にして、エンジンの `SampleSky` と同じ引き方（u = atan2(Z, X) / 2π + 0.5、
  v = asin(−Y) / π + 0.5、横は繰り返し、縦は端の texel の中心で止める線形）で引く World。
- **地面**: 高度 0 に地面のアルベド（0.3）の拡散の板（半辺 60 km）。エンジンの照り返しの項（アルベド × (太陽 + 上の空)）の物理の版で、
  雲の影も落ちる。カメラからは見えない。
- **霞**: 描かない（雲の層の外は真空）。比べるエンジンの値は霞を掛ける前の散乱光（書き出しの行 1）。
- **カメラ**: 書き出しの逆の視線行列から向き（画面の中心・左右・上下の視線）と縦の画角を求め、縦で合わせる透視のカメラにする。
  対称な透視の投影の視線と書き出しの視線の差は最大 0.22 画素（逆の視線行列の単精度の丸め）。
- **描き方**: 透明の背景・画素の中心に寄せたフィルタ（幅 0.01 画素）で、雲の散乱光（RGB）と α を描く。順に、
  1. 空だけの画（雲を隠す。`<視点>.aux.sky.pfm`）、
  2. 透過率の画（同じ格子の吸収だけの体積を光線の歩で積む描き方、16 サンプル。`<視点>.aux.transmittance.pfm` = 1 − α）、
  3. 本描画（64 サンプルずつ種を変えて A・B に重ねる。`<視点>.cycles.{hdr,seed_a,seed_b,alpha,alpha_a,alpha_b}.pfm`）。
  本描画の α も期待値は 1 − 透過率だが、散乱した標本で透明が切れるので粒が粗い（試しの描画で、窓の平均でも式と最大 0.097 違う）。
  置き方の照合には透過率の画を使う。

## 検査（`ReferenceCheck.py --cloud`）

比べる値は書き出しの視線（画面の 16 × 9 の区画の中心の画素、144 本）ごとの値。エンジンは GPU が描画と同じ式で評価した霞の前の
散乱光と透過率、Cycles は視線の画素を中心とする 3 × 3 画素の平均。

比較が成り立つ条件（満たさなければ落ちる。エンジンと Cycles の値の一致は求めない）:

1. エンジンの書き出しが `--cloud-dump` の検査に合格する。
2. 参照が読んだ書き出しのファイルのハッシュが今の撮影と同じ。カメラ・格子・視線の領域が求め直した値と同じ。対称な透視の投影で
   書き出しの視線を 0.5 画素以内で表せる。出力の画の大きさが撮影と同じ。
3. 空だけの画の視線の画素の値が、LUT を `sample_sky` で引いた値と相対 1 % 以内（同じ空・同じ向き）。
4. 透過率の画の窓の平均が、式を 4 m ごとに積んだ透過率（窓の画素の視線の平均）と 0.01 以内（同じ密度・置き方・消散係数）。
5. 収束: 1 本 512 サンプル以上で、領域ごとに A と B の窓の輝度の平均の差 1 % 以下・画素の差の RMS 10 % 以下（GrayRegions と同じ基準）。
   `--trial` はこの条件だけを外す。
6. 各領域に 3 本以上の視線があり、表の値と量が有限（未判定なら落ちる）。

`--verify` はエンジンの撮影の入力（inputs.json）と、参照の台本（`BlenderReference.py`・`CloudVolume.py`・`CloudDumpCheck.py`・
`GrayRegions.py`）のハッシュを今のファイルと照らす。

視線の領域（エンジンの値で決め、両方の描画に同じ分け方を使う。不透明度 = 1 − エンジンの透過率）:

| 領域 | 条件 | cloud_sky の視線 |
|---|---|---|
| 厚い雲 `cloud_body` | 不透明度 ≥ 0.5 | 42 |
| 縁 `cloud_edge` | 0.05 ≤ 不透明度 < 0.5、太陽との角 ≥ 40° | 22 |
| 銀の縁 `silver_lining` | 0.05 ≤ 不透明度 < 0.5、太陽との角 ≤ 20° | 9 |
| 日の当たる側 `body_sunlit` | 厚い雲で、光を返した所の平均の点から太陽への透過率 ≥ 0.7 | 15 |
| 影の側 `body_shadow` | 厚い雲で、同じ透過率 ≤ 0.5 | 7 |

量（描画ごと）: 縁の明るさ = 縁の Y / 不透明度 ÷ 厚い雲の Y / 不透明度、銀の縁 = 銀の縁の Y / 不透明度 ÷ 縁の Y / 不透明度、
影の側の暗さ = 影の側の Y ÷ 日の当たる側の Y。

## 試しの描画の結果

`.harness/runs/scene-capture/SCN-WLR-CLOUD-REF-BLENDER/`（1 本 64 サンプル、RTX 4080 の OptiX。焼き 176 秒、描画 11 秒）。
`--trial --verify` は合格、`--trial` なしは収束の条件（1 本 64 / 512 サンプル、5 領域とも未収束）で落ちる。

| 条件 | 値 | 上限 |
|---|---|---|
| 書き出しの検査 | 合格 | — |
| 投影の差 | 0.22 画素 | 0.5 |
| 空の相対差（最大） | 0.09 % | 1 % |
| 透過率の画と式の差（最大・中央値・95 %） | 0.0050・0.0005・0.0028（符号つきの平均 −0.0004） | 0.01 |
| 画素の差の RMS（厚い雲・縁・銀の縁・日の当たる側・影の側） | 0.20・0.33・0.12・0.23・0.23 | 0.10（収束） |

収束までの見込み: 画素の差の RMS はサンプル数の平方根で減るので、縁（0.33）が 0.10 を切るのは 1 本 700 サンプル前後。
64 サンプル × 2 本の描画が 11 秒なので、1 本 1024 サンプルで数分。

試しの描画の表（収束していないので比べた差は判断に使わない。SCN-WLR-CLOUD-REF で収束まで描いて分類する）:

| 領域 | エンジンの Y（cd/m²） | Cycles の Y | 比 |
|---|---|---|---|
| 厚い雲 | 19478 | 19104 | 1.02 |
| 縁 | 4622 | 3113 | 1.48 |
| 銀の縁 | 32748 | 31490 | 1.04 |
| 日の当たる側 | 14724 | 12377 | 1.19 |
| 影の側 | 13524 | 18813 | 0.72 |

| 量 | エンジン | Cycles |
|---|---|---|
| 縁の明るさ | 0.64 | 0.43 |
| 銀の縁 | 8.7 | 13.0 |
| 影の側の暗さ | 0.92 | 1.52 |

見比べの画（`cloud_cloud_sky.png`）: 雲の形と位置はエンジンと Cycles で同じ。エンジンの画には霞（空気遠近）と太陽の円盤が入り、
Cycles の画は霞なし。
