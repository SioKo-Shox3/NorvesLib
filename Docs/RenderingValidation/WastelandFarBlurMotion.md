# 荒野の遠景のぼけを、カメラを振ったときの履歴の消失で切り分ける

荒野の遠くの崖のぼけのうち、カメラが動いている間に TAA の履歴が細部を削る分を、振りながら撮った画と同じ向きで止めて
撮った画の比較で切り分けた記録。判定日: 2026-10-19（2026-10-20 にエンジンの実装の署名つきの記録の形で全 4 組を撮り直した。
下の「撮り直し」）。ブランチ `feature/scene-launcher`。タスク SCN-WLR-FAR-BLUR-MOTION。
測り方は SCN-WLR-FAR-BLUR-STATIC（`WastelandFarBlurStatic.md`）と同じ。既定の見た目は変えていない（AA とジオメトリの取り分は
開発ビルドの起動引数、台本の撮影は開発ビルドの `--camera-script` と `--capture-views` の組み合わせだけで働く）。
2026-10-22 に動きに応じた履歴の鋭さの補いを足し、昼の荒野の既定の AA を TAA にした（下の「動きに応じた履歴の鋭さの補い」。
タスク SCN-WL-FAR-AA-MOTION）。それより上の表は既定が FXAA のときの撮影。

## 撮り方

- 視点: ref_far_01（縦の画角 12.77°、横 22.5°）。1920×1080、RelWithDebInfo、決定的な撮影（1/60 秒の固定刻み）。
- 台本: `Scripts/CameraScripts/wasteland-far-pan.txt`。毎フレーム 0.03° 右へ振る（画面の中心で 2.53 画素/フレーム。端数 0.53 は
  履歴の読み直しで最もぼける半画素に近い）。どの振りも基準の視点から 1.8° 左へ置き、60 フレームで基準の向きへ戻った所を撮る。
- 履歴の消去: 台本の `epoch`（決定的な撮影のエポック。時間・TAA の履歴とジッタの列・自動露出を数え直す）。振り（motion-k）と
  止め（static-k）を同じエポックからのフレーム数 k = 0・8・30 で撮り、時間・ジッタ・露出の数え直しの影響を両者で揃える。
  k = 0 は履歴の消去の直後（履歴を使わず現在の色だけ）。static-60 は台本の後に `--capture-views` が撮る止めの 60 フレーム後の画で、
  SCN-WLR-FAR-BLUR-STATIC の撮り方と同じ。
- 台本の撮影の段取り（`Game/Input/CameraScript.h` の `home`・`epoch`・`capture=<名前>`・`wait-ready`。受け手は
  `Game/Debug/CameraScriptCapture.h`）: 台本はゲームの Tick で回り、Tick は描画の受け渡しより前なので、エポックはそのフレームの
  パケットを 0 番にし、撮影の要求はそのフレームのパケットへ写る。振りの範囲のページは最初に同じ振りを 1 回流して読み込み、
  止めの前と最初に `wait-ready`（非同期の資産・ジオメトリのページの読み込みが 30 フレーム続けて無い）で待つ。
- 組: 正解 ref2x（3840×2160・AA なし・取り分 9、同じ台本で同じ名前を撮る）、fxaa（取り分 9）、taa（`--wasteland-aa=taa`・取り分 9）、
  base（verify の撮影。既定の取り分 1・FXAA。記録だけ）。どの名前の画も、正解の同じ名前の画（2×2 を線形の光で平均）と比べる。
  範囲は正解の止めの 60 フレーム後の深度と法線から（遠景 = 1000 m より奥の地表、崖 = そのうち法線の |y| が 0.8 未満）。

検査: `python Scripts/Terrain/ReferenceCheck.py --blur-motion --capture .harness/runs/scene-capture/SCN-WLR-FAR-BLUR-MOTION --verify`。
結果は `blur_motion_check.json`、切り出しの並びは `blur_motion_ref_far_01.png`。

## 読み取り

1. **既定（FXAA）では、動きはぼけを足さない**。FXAA は履歴を持たないので、振りと止めの差は全帯域で 0.002 以内。既定の取り分の base も同じ。
   既定の構成で歩いたり振ったりしたときの遠景のぼけは、静止の切り分けの原因（標本の不足・霞・常駐の不足・LOD）がそのまま残る。
2. **TAA は動くと細部の欠けが +0.10 増える**。履歴を消した直後（k = 0）は止めと同じ（現在の色だけ）で、8 フレームでほぼ定常に達する
   （k = 8 で差の 90 %）。動きの分は静止の TAA の欠け（FXAA から +0.144）に上乗せされ、振っている間の TAA の崖の欠けは 0.476 と
   FXAA（0.225）の 2 倍になる。代わりにエイリアスは止めの TAA よりさらに −0.065 減る（履歴がぼけて階段も消える）。
3. 欠けは最も細かい帯域（σ 0〜1）に集中し、σ 2 より粗い帯域は残る。毎フレーム端数のある動き（ここでは 0.53 画素）で履歴を
   Catmull-Rom で読み直すたびに高い周波数が少し落ち、現在の色の割合 0.1 では約 9 フレーム分の読み直しが積もる、という形と合う
   （k = 8 でほぼ定常になるのも、履歴の重みが 0.9^8 = 0.43 まで減る長さと合う）。

## 直す案

既定（FXAA）では動きの分の手当ては要らない。TAA を荒野の既定にする前に、次を同じ測り方（この検査の k = 30 の差）で確かめる。

- **動きに応じた履歴の鋭さの補い**: 履歴の再投影の端数（velocity の小数部）が大きいほど、読み直しで落ちる高い周波数を補う
  （Catmull-Rom の端数ごとの減衰に合わせた逆のシャープ化を履歴に掛ける。今の書き戻しのシャープ化 0.25 は動きによらず一定で、
  履歴には掛けない）。目標は motion-30 − static-30 の欠けの差を +0.03 以下にし、エイリアスを止めの TAA より増やさないこと。
- **動きに応じた現在の色の割合**: 画面上の動きが 1 画素を超える所で現在の色の割合を 0.1 から上げる（積もる読み直しの回数を減らす）。
  欠けは減るがエイリアスが戻るので、上の補いと組にして差の表で釣り合いを決める。
- **出力より細かい履歴**（2×2 の履歴を持つ、TAAU・DLAA 相当）: 読み直しのぼけが出力の Nyquist より上へ移る。メモリと帯域は 4 倍で、
  静止の切り分けの 1 位（1 画素 1 標本のエイリアス）にも効く。費用が大きいので、上の 2 つで足りないときに比べる。
- 速さの依存は確かめていない。端数 0.5 付近が最もぼけ、整数の画素の動きではほとんどぼけないはずなので、直した後は振りの速さを
  2〜3 通り（端数 0・0.25・0.5）にして比べる。

## 動きに応じた履歴の鋭さの補い（2026-10-22、SCN-WL-FAR-AA-MOTION）

SCN-WL-FAR-AA で TAA の静止の収束（シャープ化 0.5・TAA の View の LOD の誤差 0.5 画素）を直した後は、止めの TAA の欠けが
下がった分だけ動きの分が目立ち、Catmull-Rom のままの TAA の motion-30 − static-30 は崖 +0.154・遠景 +0.143 になっていた
（掃引の組 taa-cr。エイリアスの差は +0.017）。

直したこと（`Assets/Shaders/temporal_aa.frag`、定数は `Rendering/TemporalAA.h`）:

- **履歴の再投影の補間の質**: 履歴を読む 3 次を Catmull-Rom（Keys の a = −0.5）から a = −1.0 へ鋭くした
  （`TemporalAAHistoryCubicSharpness = 1.0`）。端数 f の 4 点の重みは w0 = a·f(1−f)²、w1 = (a+2)f³ − (a+3)f² + 1、w3 = a(1−f)f²、
  w2 = 1 − w0 − w1 − w3。端数 0（止まった画・整数の画素の動き）では重みが中央の 1 画素だけになるので、止まった画は変わらない。
  行き過ぎた分は今までどおり分散の箱のクリップが抑える。
- **補間のぼけに応じた現在の色の割合**: 補間でぼける量は f(1 − f) に比例するので、両軸の 4f(1 − f) の和（0〜1）で、現在の色の
  割合を 0.1 から 0.15 へ寄せる（`TemporalAAResampleCurrentFrameWeight = 0.15`）。積もる読み直しの回数が減る。速さそのものでなく
  端数で決めるので、整数の画素の動きでは割合は変わらない。
- 開発ビルドの起動引数 `--taa-history-sharpness=<0〜1.5>`・`--taa-resample-current-weight=<0.01〜1>`（環境変数
  `NORVES_TAA_HISTORY_SHARPNESS`・`NORVES_TAA_RESAMPLE_CURRENT_WEIGHT`、ログ `TAA_MOTION_PARAMS`）で撮り比べられる。

掃引（同じ Game.exe c82f161e…、ref_far_01 を台本で振る。撮影先 `.harness/runs/scene-capture/SCN-WL-FAR-AA-MOTION-sweep/`。
値は 細部の欠け / エイリアス）:

| taa-cr | 0.5 | 0.1 | 0.182 / 0.199 | 0.344 / 0.219 | +0.154 / +0.017 | +0.143 / +0.011 |
