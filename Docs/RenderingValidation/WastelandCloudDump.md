# 荒野の雲の密度場の書き出し

荒野の雲の正解の絵（SCN-WLR-CLOUD-*）のために、エンジンの雲の密度場（3D ノイズの格子と、世界の位置からの引き方・時刻・
風のずれ）と雲の照明に使う値を書き出し、書き出しだけから求め直した雲の透過率がエンジンの描画の値と合うことを確かめた記録。
判定日: 2026-10-22。ブランチ `feature/scene-launcher`。タスク SCN-WLR-CLOUD-REF-DUMP。雲の見た目は変えていない
（式を描画と書き出しの共有の include へ移しただけ）。

ここに書いた形・式・定数を、雲の正解（Blender・Cycles の体積、`ReferenceCheck.py --cloud`）が読む**入力の契約**とする。
式や定数を変えたら、この文書・`Scripts/Terrain/CloudDumpCheck.py`・書き出しの JSON を同じ変更で直す。

## 書き出すもの（`<視点>.cloud.*`）

値は線形の Rec.709（D65）、放射輝度は cd/m²、照度は lux、ワールドは +Y が上の m。事前露出は除いてある。

| ファイル | 中身 | 形 |
|---|---|---|
| `shape_noise.u8` | 密度場の基本の形の 3D ノイズ（RGBA8 unorm。R = Perlin-Worley、G・B・A = 格子 4・8・16 から始まる反転 Worley の fbm） | 64 × 64 × 64 × 4（z, y, x, rgba） |
| `detail_noise.u8` | 細部の 3D ノイズ（R・G・B = 格子 2・4・8 から始まる反転 Worley の fbm、A = 1） | 32 × 32 × 32 × 4 |
| `sky_radiance_lut.f32` | 空の放射輝度 LUT（GPU へ上げた半精度の値。正距円筒。雲の環境光と雲の後ろの空を引く） | 128 × 256 × 4 |
| `aerial_profile.f32` | 雲までの区間の空気遠近の高度ごとの表（定数の `aerialProfile`。地面の空気遠近と同じ `SkyAerialProfile`）。行 0 = 太陽の照度 × 透過率（lux）、行 1 = 太陽の照度 × 多重散乱の表 Ψ_ms（cd/m²）、段 i は海面からの高度 i × `aerial_profile_range.x` / 127 | 2 × 128 × 4 |
| `probe.f32` | 決めた画素の視線の雲（下の行の約束。GPU が描画と同じ式で評価した値）。格子の視線 144 本の後ろに反実仮想の列 112 本 | 8 × 256 × 4 |
| `json` | 上の形・軸・FNV-1a、`cloud_layer.frag` の定数そのもの（`shader_params`）、雲の層と空のパラメータ、時刻とフレームの番号、格子の引き方・風のずれ・照明の式と係数、視線の画素 | — |

`probe.f32` の行: 0 = 雲の透過率（打ち切りの前）・描画が重ねる割合・距離で溶かす割合（SCN-WL-CLOUD-FAR-RANGE から常に 1）・進めた歩数、1 = 散乱光と光を返した所の
距離の重み付きの平均、2 = 描画の雲の放射輝度（雲までの空気遠近と溶かす割合の後）と雲までの空気遠近の透過率の RGB の平均、3 = 視線の向きと歩の端数、4 = 上の空の平均と
区間の始め、5 = 地面の照り返しと区間の終わり、6 = 視線の向きの空の LUT の値（雲の後ろの空）とその画素の深度、7 = 視線の光学的深さ・
決めた歩数・1 歩の長さ・印（1 = 雲の層を進めた、2 = 向きを求めた、4 × 診断の切り替え）。

反実仮想の列（SCN-WL-CLOUD-FAR-CAUSE。`ReferenceCheck.py --cloud-far` が読む）: 格子の上から 7 行の視線（番号 0〜111）を、同じ画素・
同じ歩の端数のまま、雲の式の診断の切り替え（`Common/CloudLayerCommon.glsl` の `kCloudDiagnostic*`）を立てて評価した列で、番号 144〜255 に
並ぶ。切り替えは列ごとに 1 → 3 → 7 と回す（1 = 細かい歩で積む。歩数の上限を 1024 へ上げる、
2 = 距離の溶かしを外す（SCN-WL-CLOUD-FAR-RANGE で溶かしそのものを外したので、今は何も変えない）、4 = 雲までの区間の空気遠近を外す。
SCN-WL-CLOUD-FAR-RANGE の前は 1 = 45 km の打ち切りを外して雲の層を出るまで進め、歩数の上限を 1024 へ上げる切り替え、2 = 30〜45 km の溶かしを外す切り替え。SCN-WL-CLOUD-FAR-COMPOSITE の前は独自の 22 km の霞を外す切り替え）。行の意味は格子の視線と同じで、7 行目の印の 4 の位より上に切り替えの値を
持つ。描画（`cloud_layer.frag`）は切り替えを使わず、既定の描画は変わらない。`--cloud-dump` の検査と `--cloud` の比べ（`CloudVolume.load_dump`）は
格子の視線だけを見る。

格子は描画のパス（`CloudLayerPass`）と書き出しのパスが起動後に GPU へ上げた texel と同じで、Game のログの `CLOUD_NOISE` の行に
FNV-1a（`shape_fnv1a64`・`detail_fnv1a64`）を残す。書き出しは同じ関数で作り直し、ファイルと JSON に同じ値を書く。

## 入力の契約

### 密度場（`SampleCloudDensity`）

- **格子の引き方**: どちらの格子も 3 方向とも繰り返し、3 次元の線形の補間（texel の中心が (i + 0.5) / 大きさ、mip 0）。値は byte / 255。
- **格子の世界の座標**: 雲の位置 p は (ワールドの x, 惑星の表面からの高度, ワールドの z)。球殻の曲がりに沿って同じ形が並ぶように、
  y は高さでなく高度で引く。高度 = |(x − カメラの x, 惑星の半径 + max(カメラの y, 1) + 向きの y × t, z − カメラの z)| − 惑星の半径。
- **基本の形**: テクスチャ座標 = (p + (風のずれ x, 0, 風のずれ z)) / 周期。周期 = 雲の形の大きさ（荒野 2500 m。SCN-WL-CLOUD-SHAPE-TUNE の前は 4500 m）。
- **細部**: テクスチャ座標 = (p + 細部の風のずれ) / (周期 × 1/8.3)。細部で縁を削るのは視線の距離 18 km まで、太陽への光の歩は最初の 3 回。
- **天気の模様**: (u, v) = 回転 (cos 0.7986, sin 0.6018) × (x, z) / (周期 × 3.7)。大きい方 = 基本の形の格子の (u + ずれ, 0.37, v + ずれ)、
  細かい方 = (v × 2.7 + ずれ, 0.71, u × 2.7 + ずれ)。天気 = clamp(大.r × 0.55 + 大.g × 0.2 + 細.r × 0.25)、
  覆いの印 = smoothstep(1 − 覆う割合 − 0.03, 1 − 覆う割合 + 0.08, 天気)（SCN-WL-CLOUD-SHAPE-TUNE の前は −0.08・+0.22）。印が 0.001 以下なら密度 0。
- **高さの形**: 層の中の高さの割合 h（0 = 底、1 = 頂）で、clamp(remap(h, 0, 0.07, 0, 1)) × clamp(remap(h, 頂 × 0.55, 頂, 1, 0))、
  頂 = mix(0.35, 1, 印)。
- **密度**: 低い周波数の fbm = G × 0.625 + B × 0.25 + A × 0.125、base = clamp(remap(R, fbm − 1, 1, 0, 1))、
  base = clamp(remap(base × 高さの形, 1 − 印, 1, 0, 1) × 印 × 3)（倍率 3 は SCN-WL-CLOUD-SHAPE-TUNE で足した）。細部の fbm（R・G・B を同じ重み）を mix(fbm, 1 − fbm, clamp(4h)) にして、
  密度 = clamp(remap(base, その値 × 0.35, 1, 0, 1))。remap の分母は 1e-5 より小さくしない。
- **時刻と風のずれ**: 時刻 t（決定的な撮影では 1/60 秒の固定刻みの TotalTime）、風 (8, 3) m/s。基本の形のずれ = fmod(風 × t, 周期)、
  細部のずれ = fmod((風 x × 1.6, −1.5, 風 z × 1.6) × t, 細部の周期)、天気のずれ = fract(回転 × 風 × t / 天気の周期)、
  細かい方のずれ = fract((v, u) × 2.7 + (0.31, 0.53))。JSON の `shader_params` に実際の値がある。

### 視線の進め方（`MarchCloudLayer`）

- 惑星の中心を原点に、雲の層（荒野は地表から 2500〜3600 m）の球殻と視線の交点の区間を、層に入る所から出る所まで進める
  （SCN-WL-CLOUD-FAR-RANGE から。前は最長 45 km で、区間の始めが 45 km より先の視線には雲が無かった）。地面に当たる視線には雲が無い。
  地平線の向きの区間は荒野で約 36 km（層に入る距離 約 180 km）。
- 歩数 = clamp(int(区間 / 90 m), 32, 192)（SCN-WL-CLOUD-FAR-RANGE の前は上限 96）、1 歩の長さ = 区間 / 歩数。歩の位置 = 始め + (i + 端数) × 1 歩。
- 端数 = interleaved gradient noise（画素の中心 + 5.588238 × (フレームの番号 mod 1024) を (0.06711056, 0.00583715) と内積し、
  52.9829189 倍の小数部）。描画と同じ画素・同じフレームの値なので、書き出しの視線は描画のその画素の視線と同じになる。
- 層の外の歩と密度 0.001 以下の歩は飛ばす。1 歩の透過率 = exp(−密度 × 消散係数 × 1 歩)（荒野の消散係数 0.006 /m）。
  透過率が 0.01 を下回ったら進むのをやめる。

### 雲の照明に使う値

- **太陽**: 向きは空の太陽の仰角・方位角、照度は空の太陽の地表の照度（`ComputeSunGroundIlluminance`。JSON の `lighting`）。
  太陽への光学的深さは 6 回（最初の歩 70 m、1.8 倍ずつ）、層の頂を越えたら打ち切る。
- **位相関数**: mix(HG(cos, 0.8 s), HG(cos, −0.3 s), 0.3)、s = 0.5^回。HG の分母は 1e-4 より小さくしない。
- **多重散乱の近似**: 3 回の和 Σ 0.5^i × exp(−光学的深さ × 0.5^i) × 位相_i。
- **空の光**: 上の空の平均 = 0.2 × (天頂 + 仰角 30° の 4 方向の空の LUT の値)。地面の照り返し = 地面のアルベド × (太陽の照度 ×
  max(太陽の y, 0) / π + 上の空の平均)。環境光 = 上の空の平均 × mix(0.6, 1, h) + 0.5 × 照り返し × mix(1, 0.3, h)。
- **積分**: 散乱光 += 透過率 × σ (太陽の照度 × 太陽の項 + 環境光) × (1 − exp(−σ × 1 歩)) / max(σ, 1e-7)。
- **雲までの空気遠近（SCN-WL-CLOUD-FAR-COMPOSITE）**: 描画の放射輝度 = 散乱光 × T_air(d) + S_air(0, d) × 不透明度
  （d は光を返した所の距離の平均。SCN-WL-CLOUD-FAR-RANGE の前は全体に溶かす割合 1 − smoothstep(30 km, 45 km, 区間の始め) を掛けていた）。T_air・S_air はカメラから d までの区間の
  RGB の透過率と散乱光で、地面の空気遠近（`VolumetricsCommon.glsl` の `MarchFogAndAerial` の空の媒質の分。霧は数えない）と同じ式・
  同じ媒質・同じ高度ごとの表を 32 歩の中点則で積む: 高度は球の上（カメラの y ＋ `aerial_perspective.w`）、`aerial_perspective.z` より
  手前は数えず、それより先は `aerial_perspective.y` 倍、各点の源は Rayleigh と Mie の位相 × 表の行 0 と、散乱係数 × 表の行 1。
  定数は `shader_params` の `aerial_perspective`（有効・距離の倍率・掛け始める距離・ワールドの y = 0 の海面からの高度）・
  `rayleigh_extinction_and_scale_height`・`mie_extinction_and_scattering`（消散係数・スケールハイト・散乱係数・位相の異方性）・
  `aerial_profile_range`。空気遠近が無効なら T_air = 1、S_air = 0（地面と同じく何も掛けない）。雲の後ろの空（視線の向きの空の LUT の値）は
  同じ区間の散乱光をすでに含み、合成で 1 − 不透明度 × 溶かす割合を掛けて残るので、区間の散乱光は雲が覆う割合だけ足す
  （手前の大気を二重に数えない）。前の版の独自の霞（散乱光 × e^(−d/22 km) + 空 × 不透明度 × (1 − e^(−d/22 km))）は外した。

## 検査（`ReferenceCheck.py --cloud-dump`）

合否:

1. 書き出しの形式・ファイルの形・値が有限。撮影の起動引数に `--cloud-dump`、Game のログに `CLOUD_DUMP` と保存の印がある。
   格子のファイルの FNV-1a が JSON の値と、ログの `CLOUD_NOISE`（描画のパスと書き出しのパスが GPU へ上げた値）と同じ。
2. 定数が契約どおり（周期の逆数・風のずれ・天気のずれ・フレームの位相・層の高度を、雲の層・時刻・フレームの番号から求め直した値と 1e-4 以内）。
3. 既定の視点 cloud_sky は視線がすべて空の画素（地形の入る ref_far_01 などは空でない視線の数を記録する）で、雲のある視線（不透明度 0.05 以上）が 10 本以上、厚い視線（0.5 以上）が 3 本以上ある。
4. 視線ごとに、画素から求め直した向き（1e-4）・歩の端数（0.01）・区間と 1 歩の長さ（相対 1e-4）・歩数が GPU と合う。
5. 書き出した格子からエンジンの式で求め直した雲の透過率が、GPU の値と全部の視線（地形の入る視点の空でない画素の視線も）で差の絶対値
   0.01（1 %）以内。求め直しは GPU が書き出した単精度の視線の向きで進め（画素から求めた向きとの差は 4 で照らす）、歩の位置は GPU が
   書き出した区間（始まり・終わり・歩数・1 歩の長さ）に固定して、位置・惑星の中心からの距離・高度を GPU と同じ単精度で求める（区間は 4 で
   自分の値と照らす）。地平線の近くを長く進む視線は、縁の締まった雲を 1e-4 rad の向きの差や単精度の高度の丸め（6.36e6 m で 0.5 m）で別の所へ
   抜ける（SCN-WL-CLOUD-SHAPE-TUNE の ref_far_01 の画素 (780.5, 780.5) は倍精度の位置で差 0.031、単精度の位置で 0.0002）。

記録（合否に使わない）: 光学的深さ、散乱光・描画の放射輝度・上の空の平均・照り返し・雲の後ろの空の相対差。

## 全画素の雲の不透明度の画像（`--wasteland-cloud-opacity`）

256 本の視線だけでは雲の塊・切れ間・縁を画素で測れず、描画の画面からは不透明度を取れない（`cloud_layer.frag` は前乗算のアルファで
RGB だけを書き、画面のアルファを保つ）。そのため、雲の書き出しと同じフレーム・同じ定数で、画面の全画素の雲だけの不透明度を書く。
タスク SCN-WL-CLOUD-OPACITY-AOV。開発ビルドだけの機能で、Release の Game は起動引数を無視し（警告だけ）、専用の資源もパスも作らない
（`CloudProbePass` は統計が有効な構成だけにある）。

| 何 | どこ | 何をするか |
|---|---|---|
| `--wasteland-cloud-opacity` | `Game/GameApplicationHandler.cpp`・`Game/Debug/MultiViewCapture.cpp` | `--cloud-dump` と併せて使う（無ければ起動で失敗）。環境変数 `NORVES_CLOUD_OPACITY=1` を置き、`CloudProbePass` が不透明度の画像も書く（ログに `CLOUD_OPACITY`） |
| `cloud_layer_opacity.frag` | `Assets/Shaders/` | `cloud_layer.frag` と同じ式・同じ深度の判定・同じ歩の端数（`gl_FragCoord` とフレームの位相）で全画素の雲を進める |
| `CloudProbePass` | `Library/Core/Private/Rendering/CloudLayerPass.inl` | 視線の 1 枚と同じ記述子セット（同じ定数・同じ深度）で、深度と同じ大きさの RGBA32F の 1 枚（`Capture.CloudOpacity`）へ書き、グラフの外へ出す。大きさが深度と違うフレームは書かない |
| 読み戻し | `FrameCaptureReadbackHelper` | 雲の書き出しを写すフレームで、同じフレームの 1 枚を、フレームの枠ごとの読み出し先（`m_CloudOpacityReadbackSlots`）へ写す。枠はそのフレームの完了を待ってから読み、次に同じ枠を使うフレームまで写したものに触らない |
| `SaveCapturedCloudOpacity` | `Library/Core/Public/Rendering/FrameCaptureHdrWriter.h` | `<視点>.cloud.opacity.f32` と `<視点>.cloud.opacity.json` を書く |
| `ReferenceCheck.py --cloud-opacity` | `Scripts/Terrain/CloudOpacityCheck.py` | 下の合否を確かめ、`cloud_opacity_check.json` と見える形の画像 `cloud_opacity_<視点>.png`（灰 = 不透明度、茶 = 地形のマスク、十字 = 視線の位置で緑が合格）を書く |

画像（`.cloud.opacity.f32`）は [行, 列, RGBA] の 32 bit 浮動小数（リトルエンディアン）。**行 0 が画面の上**、列 0 が左
（`gl_FragCoord` と同じ向き。画素の中心は +0.5）。

| チャンネル | 中身 |
|---|---|
| r | **雲だけの不透明度（溶かす割合を掛けた後）** = (1 − 雲の透過率) × fade。`cloud_layer.frag` が重ねるアルファと同じ値。霞（空気遠近）・太陽の円盤・地形を含まない。地形の画素は 0 |
| g | 1 − 雲の透過率（溶かす割合を掛ける前）。地形の画素は 0 |
| b | 地形のマスク（深度が有限で 0.999999 より小さい画素 = 空でない画素は 1、空の画素は 0） |
| a | 打ち切りの距離へ溶かす割合（雲の無い視線・地形の画素は 1） |

合否に使う値は r（溶かす割合を掛けた後）とした。画面に重なる雲そのものを測るため。今の式では溶かす割合は常に 1
（SCN-WL-CLOUD-FAR-RANGE で溶かしを外した）なので r と g は同じ値になる。

JSON（`.cloud.opacity.json`、形式 `norves_cloud_opacity_v1`）には、同じフレームの雲の書き出しの名前、フレームの番号、時刻、
歩の端数の位相に使ったフレームの番号、画面の大きさ、画像の形・向き・チャンネル、カメラ（位置と `cloud_layer.frag` の定数の
逆の射影の行列。視線の向き = normalize(逆の射影 × (uv × 2 − 1, 1, 1) の点 − 位置)、uv = 画素 ÷ 画面の大きさ）、地形と空の
画素の数・空の画素の不透明度の平均と最大を書く。

### 合否（`ReferenceCheck.py --cloud-opacity`）

1. 形式・ファイルの形が JSON と合い、撮影の起動引数に `--wasteland-cloud-opacity` と `--cloud-dump`、Game のログに `CLOUD_OPACITY`
   と保存の印がある。雲の書き出しと同じフレームの番号・時刻・画面の大きさ・逆の射影の行列・カメラの位置。
2. 値がすべて有限で、r・g・a が 0〜1、地形のマスクが 0 か 1。
3. 地形のマスクの外だけに値がある（マスクが 1 の画素の r・g が 0）。
4. 雲の書き出しの 256 本の視線（格子の 144 本と、診断の切り替えを立てた反実仮想の 112 本）ごとに、書き出しの視線の向きを記録の
   射影で画素へ戻し（書き出しの画素の中心との差 1.5 画素以内。GPU の単精度の視線の向きは 2.5〜2.8e-4 rad ずれ、ref_far_01 の横の画角 22.8° で 1.2 画素に当たる）、その画素の r と視線の重ねる割合、空の画素では g と
   1 − 透過率の差が 0.01 以内。地形のマスクと視線の深度の空かどうかが合う。
5. 全視点で雲のある格子の視線（不透明度 0.05 以上）が 10 本以上ある。

反実仮想の 112 本は、格子の上から 7 行と同じ画素を細かい歩（歩数の上限 1024）で積んだ値などだが、描画の画像との差も同じ 0.01 で
抑える（256 本のどれかの値がずれたら落ちる）。反実仮想の列だけの差の最大は別に記録する（`diagnostic_opacity_max_abs`）。
