# 撮影の画と記録のカメラのずれ

荒野の正解の絵（SCN-WLR-*）の照合で、エンジンの撮影の画が、撮影の記録のカメラ（`<視点>.aov.json` の `camera`）から視点ごとに
違う量ずれていた件の原因と直し方、検査、ずらしありで描いた旧参照の扱いの記録。
判定日: 2026-10-20。ブランチ `feature/scene-launcher`。タスク SCN-WL-CAMERA-OFFSET。

## 症状

エンジンの深度と、記録のカメラのまま描いた Blender の深度から最小二乗で求めた小数のずれ（`ReferenceCheck.depth_subpixel_shift`）が、
視点ごとに違い、起動し直しても同じだった。深度 295〜613 m・画面の 4 列で同じ量なので、位置ではなく向きのずれ。
それまでの参照（SCN-WLR-MATERIAL-*・SCN-WLR-CYCLES-LIT）は、このずれだけ Blender のカメラをずらして揃えて描いていた。

## 原因

`CameraViewConstants::BuildViewMatrix` が視線行列を `CreateLookAt(位置, 位置 + 前, 上)` で作っていた。注視点 `位置 + 前` を
float で足すと、座標の大きい所では丸めの刻みが大きく（1024〜2048 m で 1.2e-4、2048〜4096 m で 2.4e-4）、`CreateLookAt` の中で
`位置 − 注視点` に戻した前の向きが、その刻みだけ傾く。荒野の照合の視点は 2 km 前後の座標にあり、縦の画角 6.1° の望遠
（1 画素 ≈ 1e-4 ラジアン）なので、傾きが 1 画素近くになる。量は位置と向きの成分の丸め方で決まるので視点ごとに違い、
起動し直しても変わらない。

最初に疑った撮ったフレームのジッタは原因ではない。荒野の既定は FXAA で投影のジッタを掛けず、ref_cliff_02 の 0.779 画素は
TAA のジッタの幅（±0.5 画素）を超える。

記録のカメラから前の作り方の丸めを計算した量（`CameraOffset.lookat_rounding_px`）と、参照を描いたときに深度から求めたずらし量:

| 視点 | 深度から求めたずらし（右, 上）[画素] | 丸めから計算した量（右, 上）[画素] |
|---|---|---|
| ref_cliff_01 | +0.243, +0.027 | +0.261, +0.038 |
| ref_cliff_02 | +0.779, −0.004 | +0.834, +0.000 |
| ref_ground_02 | +0.239, −0.024 | +0.238, −0.009 |
| ref_ground_01 | 0（0.019 で許容内） | −0.000, −0.002 |
| ref_far_02 | 0（0.009） | +0.023, −0.002 |
| ref_far_01 | −0.107, −0.158 | −0.000, +0.010 |

ref_far_01 のずれは丸めでは説明できない（遠景で深度の勾配が小さく、ずれの推定が粗い。直した後の値はまだ測っていない）。

## 直し方

`BuildViewMatrix` は、原点から前の向きへの視線（`CreateLookAt(原点, 前, 上)`）で回転を作り、位置は後から平行移動で掛ける
（`回転 × 平行移動(−位置)`）。前の向きは記録の値のまま使われ、`位置 + 前` の打ち消しが無くなる。平行移動の成分は前と同じ
`−(軸 · 位置)`。投影・ジッタ・逆行列の作り方は変えていない。

## 検査

`python Scripts/Terrain/ReferenceCheck.py --camera-offset --engine <撮影先> [--verify]`（本体は `Scripts/Terrain/CameraOffset.py`）。
既定の視点は ref_cliff_01・ref_cliff_02。記録のカメラのまま補正なしで Blender の深度を描き（`BlenderReference.py --depth`。
深度の描画はカメラをずらさず、`--camera-shift-hint` も深度からの自動補正も使わない。無いか撮影のカメラと違えばその場で描いて
`<撮影先>/blender/` に保存する）、次で落とす:

- Blender の記録のカメラ・画素数が撮影と違う、Blender のカメラの姿勢の行列が記録のカメラから作った行列と違う、ずらし量が 0 でない
- エンジンの深度とのずれの残り（右・下の長さ）が 0.05 画素を超える
- `--verify` では撮影の入力と Blender の入力（台本・地形のメッシュ・PLY）が今のファイルと違う

報告は `<撮影先>/camera_offset_check.json`（ずらし量 0、残りのずれ、前の作り方の丸めの量）。

ずれはエンジンの深度が 3 km 未満の画素で測る（法線・アルベドの照合の判定の範囲と同じ）。3 km より遠い所は地形の形がエンジンと
書き出しで違い、画面の列ごとにずれが揃わない（ref_cliff_02 の全画面の値は列ごとに −0.03〜+0.17 画素とばらつく）。全画面の値と
画面の 4 列ごとの値は記録だけする。

### 結果

撮影: `CaptureScene.ps1 -Scene wasteland -Configuration RelWithDebInfo -Hdr -Aov -Views ref_cliff_01,ref_cliff_02
-GameArgs wasteland-common-light,wasteland-hide=all,wasteland-finest-lod -LaunchPerView`（`.harness/runs/scene-capture/SCN-WL-CAMERA-OFFSET`）。
Blender の深度はずらし 0 で描いた（ref_cliff_01 は 73 区画・6528 万三角形で 290 秒、ref_cliff_02 は 54 区画・4611 万三角形で 67 秒）。

| 視点 | 直した後の残り（右, 下）[画素] | 長さ | 画面の 4 列 | 全画面（記録だけ） | 直す前の撮影の同じ測り方 |
|---|---|---|---|---|---|
| ref_cliff_01 | −0.009, +0.009 | 0.013 | −0.012〜+0.007 / −0.002〜+0.013 | −0.009, +0.009 | +0.243, −0.027 |
| ref_cliff_02 | +0.006, +0.032 | 0.032 | −0.034〜+0.056 / +0.016〜+0.038 | +0.101, +0.047 | +0.837, +0.019 |

直す前の撮影（SCN-WLR-CYCLES-LIT の撮影。記録のカメラは同じ）を同じ Blender の深度で 3 km 未満で測ると、ずれは丸めから計算した
量（+0.261・+0.834）とほぼ同じで、4 列とも揃う（ref_cliff_02 は +0.808〜+0.879）。参照を描いたときの ref_cliff_02 の +0.779 は
全画面で測っていたので、遠くの形の違いが混ざって小さく出ていた。

## 旧参照の移行

直す前に描いた参照は、ずらし量を描画の記録（`camera_shift_px`）と参照の署名（`cycles/reference.json` の `cameras`）に持つ。

- ずらしありの旧参照（SCN-WLR-CYCLES-LIT の ref_cliff_01・ref_cliff_02・ref_far_01・ref_ground_02）は、領域の平均の比較
  （`--gray`・`--lit`）に限って使い続ける。参照の署名は変わらないので、エンジンを撮り直せばそのまま比べられる。
  `--lit` の標本の位置の検査は、記録のカメラ（ずらし 0）からの残り（測ったずれ + 材質のずらし）で照らす。直した撮影は記録の
  カメラに揃うので、旧参照のずらしの分だけ参照の方がずれていて、それは領域の平均には効かない程度として扱う。
  SCN-WLR-CYCLES-GRAY の 2 視点はずらし 0 で描いてあり、そのまま使える。
- 画素ごとの比較（`--albedo`・`--normal`・`--projection`）は、参照がずらしありなら「ずらし 0 で描き直すまで古い」として落とす。
- 以後の新しい描画はずらし 0 で描く。`ReferenceCheck.py --record-reference`（`RefSplit.write_reference`）は、ずらしありの
  参照の記録を書かない。

## 回帰の撮影

`Scripts/Terrain/CaptureRegression.ps1 -Item SCN-WL-CAMERA-OFFSET`（before は直す前の Game.exe、after は直した後。RelWithDebInfo と
検証レイヤー）。4 シーンとも撮影の欠け・真っ黒・検証レイヤーのエラーは無い。

| シーン | PSNR [dB] | 平均の差 | 画像の小数のずれ（右, 下）[画素] |
|---|---|---|---|
| rendering3dtest | 61.9 | +0.000 | −0.000, −0.000 |
| sandbox | 69.2 | +0.000 | −0.000, +0.000 |
| mega-bananas | 46.1 | +0.003 | −0.000, −0.000 |
| night-village | 42.4 | −0.002 | −0.021, −0.010 |

前の項目の回帰の撮影（変更なしの揺らぎ）は mega-bananas 約 60 dB・night-village 約 69 dB なので、差はこの変更による。
night-village は画面の 4 列で揃った 0.01〜0.03 画素のずれで、大きな座標のカメラで同じ丸めが直った分。mega-bananas は全体の
ずれが無く、差は細い輪郭の点だけ（視線行列の成分の最後の桁の違いで、画素の中心にかかる三角形の縁の判定が変わる）。
差の画像を開き、形・明るさ・影の変化が無いことを確かめた。
