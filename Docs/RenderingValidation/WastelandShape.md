# 荒野の地形が丸く粗く見える原因の切り分け

ユーザーの所見（2026-10-22、確認 2）「地形の造形が荒い」（崖も斜面も粘土のように丸く、棚・割れ目・角が無い）について、
直す前に原因を LOD・崖の生成・高さの格子の段・材質の陰影に分けた記録。判定日: 2026-10-24。ブランチ `feature/scene-launcher`。
タスク SCN-WL-SHAPE-CAUSE。値は変えていない。

## 撮り方

手本の 5 視点（ref_far_01・ref_far_02・ref_cliff_01・ref_cliff_02・ref_ground_02）を、同じ Game.exe（RelWithDebInfo）で次の 3 組に撮った。
どれも共通の照明（`--wasteland-common-light`）・灰色の材質（`--wasteland-gray-material`）・雲と草と砂利と建物と霞を外し（`--wasteland-hide=clouds+foliage+gravel+buildings+aerial+fog`）、
崖錐の岩は既定の描画と同じ数を置き（`--wasteland-talus-limit=off`。灰色の材質の撮影が崖錐の岩を視点から 300 m に限る制限を外す。
ログ `WASTELAND_TALUS_GRAY_LIMIT off casters=96 fragments=274965 main_lod_floor_px=1.00`）、AA は FXAA（ジッタの無い同じ画素で 3 組を比べるため）。
`-Hdr -Aov` で深度・陰影の法線・三角形の面の幾何の法線の AOV を書く。

最も細かい LOD（許容 1e-6 画素）で崖錐の岩 27 万個を段 0 で描くと、MegaGeometry の BVH のたどりの列（節・葉とも 2^22）が
約 1,400 万要素溢れて ref_cliff_01 の地形がまるごと抜ける（試しの撮影 `scene-capture/SCN-WL-SHAPE-CAUSE-try/finest-talus/`）。
そこで制限を外すときは、崖錐の岩のメッシュだけ主のカメラの LOD の許容に下限 1 画素（通常の LOD と同じ。`MegaMeshMaterial::MainLodFloorPixels`）を付け、
岩は 3 組とも通常の段で描き、地形だけを組ごとの段で描く（溢れ 0）。岩の形は 3 組で同じなので比べの外。

| 組 | 起動引数の差 | 置き場（`.harness/runs/scene-capture/SCN-WL-SHAPE-CAUSE/`） |
|---|---|---|
| (a) 通常の LOD | なし | `lod-default/` |
| (b) 最も細かい LOD | `--wasteland-finest-lod` | `lod-finest/` |
| (c) 崖の手続きの変形なし | `--wasteland-finest-lod`・`--wasteland-cliff-detail=off` | `cliff-detail-off/` |

(c) の切り替え: 崖の細部（`Tools/AssetCook/TerrainCliffDetail.cpp` の急な升目の 0.25〜2 m の細分・棚・割れ目・最大 2.5 m の押し出し）は
クックの段で区画のメッシュに焼かれるので、崖の細部を焼く範囲に掛かる近景の 25 区画と遠景の castle の段の 42 メッシュを、
細部を焼かない生成 `terrain-tile:dem-plain:<x>,<z>` で別の論理パス（`Assets/Models/WastelandTerrainCliffOff/`、一覧は
`Assets/AssetSets/WastelandTerrainCliffOff.json`。`Scripts/Terrain/WriteTerrainAssetSet.py --write` が書く）へ焼いた。既定のクックの結果は上書きしない。
Game は開発ビルドで `--wasteland-cliff-detail=off` のときだけ、その置き場にクック済みがある区画を差し替える（ログ `WASTELAND_CLIFF_DETAIL_OFF swapped=<数>`）。
既定の描画は変わらない。焼き直しは `Scripts/CookAssets.ps1 -OnlyLogicalPath 'Assets/Models/WastelandTerrainCliffOff/*'`。

## 測り方

`python Scripts/Terrain/ReferenceCheck.py --shape-cause --capture-root .harness/runs/scene-capture/SCN-WL-SHAPE-CAUSE --verify`
（`Scripts/Terrain/ShapeCause.py`）。幾何の法線は、可視バッファの解決（`Common/VisibilityResolve.glsl`）が画素の三角形の 3 頂点の辺の外積で
求めた面の法線（頂点の法線の側へ向ける）を、撮影の AOV（`<視点>.aov.geometric_normal.pfm`。`gbuffer_aov.frag` が八面体の 12 + 12 ビットに
詰める。角の誤差は 0.05° 程度）から読む。輝度の段ではなく形そのものを測る。灰色の材質の GBuffer の法線は頂点の法線で、形の丸めを含むので
形の物差しにしない。深度から戻した位置の微分は使わない（D32 の深度の量子化で、遠景の平らな面にも偽の折れ目と差が出る）。
深度は世界座標の範囲・距離・格子の段を引くのと、輪郭（隣との深度の飛び）を外すのにだけ使う。どの視点も地形の画素の 100 % で幾何の法線が読める。

| 量 | 意味 | 重ね画の色 |
|---|---|---|
| 格子の限界 | 高さの格子の 1 升（近景 1 m・castle 2 m・mid 8 m・far 16 m・outer 32 m。`horizon.json` の levels）が 4 画素以上に写る画素の割合。升の中の形は格子からは来ない | 青 |
| LOD の差 | (a) と (b) の幾何の法線の角の差が 8° を超える画素の割合 | 赤 |
| 崖の生成の差 | (b) と (c) の差（同じ測り方） | 緑 |
| 材質の陰影 | (a) の GBuffer の法線（陰影に使う頂点の法線）と幾何の法線の角の差が 15° を超える画素の割合。陰影が形より丸い所 | 黄 |
| 折れ目の密度 | 幾何の法線が 4 画素の間で 20° を超えて曲がる画素の割合（丸いほど小さい）。面の法線なので、三角形の継ぎ目の折れを数える | — |

画面を 3 行 × 4 列の升に分け、升ごとの値と世界座標の範囲（5〜95 百分位）を `<置き場>/shape_cause.json` に書き、
視点ごとの並べた画（上: 写真・(a) の撮影・原因の重ね、下: 3 組の幾何の法線の陰影）を `<置き場>/shape_cause/<視点>.png` に書く。

3 組は同じ Game.exe（`ab0adb16…`、RelWithDebInfo）で撮った（`inputs.json`）。(c) は近景と castle の段の 67 区画を差し替えた（`WASTELAND_CLIFF_DETAIL_OFF swapped=67`）。
3 組とも崖錐の岩を全部置き（`fragments=274965`）、BVH のたどりの列の溢れは 0（`MEGA_CAPACITY bvh_overflow=0`）。

## 結論

| 順位 | 原因 | 証拠（折れ目の密度は (a)・(b)・(c) の順） | 効く場所 |
|---|---|---|---|
| 1 | 格子の限界（近景の 1 m の DEM に 1 m より細かい凹凸が無い） | 近景の谷床は 1 升が数百画素に写り（格子の限界 99〜100 %）、3 組とも折れ目 0〜1 %。面の法線の陰影は数 m の平らな三角形の継ぎ合わせ | 全視点の近景の谷床 |
| 2 | 崖の生成の設定（壁の細部が縦の溝に偏り、角と棚が浅い） | 崖の生成が壁の折れ目を大きく足す: ref_far_02 の Setting Hen Butte 45 → 71 %、ref_cliff_01 の Battleship Rock の壁 44 → 60 %・33 → 47 %、ref_far_01 の castle の段の崖 46〜56 → 58〜69 %。足しているのは縦の溝で、上端の角・連続する水平の棚・壁から崖錐へ移る塊は (b) と (c) の面の法線で同じに丸い | 崖の細部の範囲の壁（近景の 4 範囲と castle の 5 範囲） |
| 3 | 材質の陰影（陰影の頂点の法線が形より丸い） | GBuffer の法線と面の法線の差が 15° を超える画素: ref_far_01 の castle の段 22〜32 %、ref_far_02 の Setting Hen Butte 31 %、ref_cliff_01 の壁 14〜20 %、ref_ground_02 のビュート 14〜17 %。近景の谷床は 0 % | 0.3 m/画素より遠い崖の壁 |

DEM の 1 m の格子は裸地の標高で、写真の谷床の流路の縁・小さな段差・礫の起伏（0.1〜1 m）を持たない。崖の生成（最大 2.5 m の押し出し）は崖の範囲の急な面だけに効き、
谷床と崖錐の緩い面は格子のまま描かれる。崖の壁は崖の生成で折れ目が増えているが、増えた折れ目は縦の溝で、写真の崖の水平の地層の棚と上端の角は作っていない。
遠くの崖が丸く見えるのは、形（面の法線の折れ目 55〜71 %）より、陰影の頂点の法線が形を均した分（差 15° 超が 22〜32 %）が大きい。
前の版（深度から戻した位置の微分）は D32 の深度の量子化を折れ目として数えていたので、LOD と材質の陰影を大きく見積もっていた（LOD の差 64〜79 %・材質の陰影 39〜61 %）。

## 既知の限界

- 折れ目と差の画素は面の法線から測るので、1 画素に複数の三角形が入る遠景（最も細かい LOD の 0.5 m/画素より遠い崖）では、画素が拾う三角形で値が揺れる。値は 3 組の比べにだけ使う（絶対の目標にしない）。
- 面の法線は可視バッファで解決した画素だけが持つ（MegaGeometry の地形・岩）。ラスタの GBuffer で描く物は読めない値（-1）になる。荒野の 5 視点の地形の画素はすべて読めた。
- 遠景の格子の段の量は、崖の生成と材質の陰影から分けて測っていない（段を細かくした撮影が無い）。
- 崖錐の岩（崖錐の散布と崖のスキャン）は 3 組とも通常の段で同じに置いたので、岩の形は比べの外。最も細かい LOD で岩も段 0 で描くと BVH のたどりの列が溢れて地形が抜ける。
