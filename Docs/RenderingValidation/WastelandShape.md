# 荒野の地形が丸く粗く見える原因の切り分け

ユーザーの所見（2026-10-22、確認 2）「地形の造形が荒い」（崖も斜面も粘土のように丸く、棚・割れ目・角が無い）について、
直す前に原因を LOD・崖の生成・高さの格子の段・材質の陰影に分けた記録。判定日: 2026-10-24。ブランチ `feature/scene-launcher`。
タスク SCN-WL-SHAPE-CAUSE。値は変えていない。

## 撮り方

手本の 5 視点（ref_far_01・ref_far_02・ref_cliff_01・ref_cliff_02・ref_ground_02）を、同じ Game.exe（RelWithDebInfo）で次の 3 組に撮った。
どれも共通の照明（`--wasteland-common-light`）・灰色の材質（`--wasteland-gray-material`）・雲と草と砂利と建物と霞を外し（`--wasteland-hide=clouds+foliage+gravel+buildings+aerial+fog`）、
崖錐の岩は既定の描画と同じ数を置き（`--wasteland-talus-limit=off`。灰色の材質の撮影が崖錐の岩を視点から 300 m に限る制限を外す。
ログ `WASTELAND_TALUS_GRAY_LIMIT off casters=96 fragments=274965 main_lod_floor_px=1.00`）、AA は FXAA（ジッタの無い同じ画素で 3 組を比べるため）。
`-Hdr -Aov` で深度・陰影の法線・三角形の面の幾何の法線の AOV を書く。

最も細かい LOD（許容 1e-6 画素）で崖錐の岩 27 万個を段 0 で描くと、MegaGeometry の BVH のたどりの列（節・葉とも 2^22）が
約 1,400 万要素溢れて ref_cliff_01 の地形がまるごと抜ける（試しの撮影 `scene-capture/SCN-WL-SHAPE-CAUSE-try/finest-talus/`）。
そこで制限を外すときは、崖錐の岩のメッシュだけ主のカメラの LOD の許容に下限 1 画素（通常の LOD と同じ。`MegaMeshMaterial::MainLodFloorPixels`）を付け、
岩は 3 組とも通常の段で描き、地形だけを組ごとの段で描く（溢れ 0）。岩の形は 3 組で同じなので比べの外。

| 組 | 起動引数の差 | 置き場（`.harness/runs/scene-capture/SCN-WL-SHAPE-CAUSE/`） |
|---|---|---|
| (a) 通常の LOD | なし | `lod-default/` |
| (b) 最も細かい LOD | `--wasteland-finest-lod` | `lod-finest/` |
| (c) 崖の手続きの変形なし | `--wasteland-finest-lod`・`--wasteland-cliff-detail=off` | `cliff-detail-off/` |

(c) の切り替え: 崖の細部（`Tools/AssetCook/TerrainCliffDetail.cpp` の急な升目の 0.25〜2 m の細分・棚・割れ目・最大 2.5 m の押し出し）は
クックの段で区画のメッシュに焼かれるので、崖の細部を焼く範囲に掛かる近景の 25 区画と遠景の castle の段の 42 メッシュを、
細部を焼かない生成 `terrain-tile:dem-plain:<x>,<z>` で別の論理パス（`Assets/Models/WastelandTerrainCliffOff/`、一覧は
`Assets/AssetSets/WastelandTerrainCliffOff.json`。`Scripts/Terrain/WriteTerrainAssetSet.py --write` が書く）へ焼いた。既定のクックの結果は上書きしない。
Game は開発ビルドで `--wasteland-cliff-detail=off` のときだけ、その置き場にクック済みがある区画を差し替える（ログ `WASTELAND_CLIFF_DETAIL_OFF swapped=<数>`）。
既定の描画は変わらない。焼き直しは `Scripts/CookAssets.ps1 -OnlyLogicalPath 'Assets/Models/WastelandTerrainCliffOff/*'`。

## 測り方

`python Scripts/Terrain/ReferenceCheck.py --shape-cause --capture-root .harness/runs/scene-capture/SCN-WL-SHAPE-CAUSE --verify`
（`Scripts/Terrain/ShapeCause.py`）。幾何の法線は、可視バッファの解決（`Common/VisibilityResolve.glsl`）が画素の三角形の 3 頂点の辺の外積で
求めた面の法線（頂点の法線の側へ向ける）を、撮影の AOV（`<視点>.aov.geometric_normal.pfm`。`gbuffer_aov.frag` が八面体の 12 + 12 ビットに
詰める。角の誤差は 0.05° 程度）から読む。輝度の段ではなく形そのものを測る。灰色の材質の GBuffer の法線は頂点の法線で、形の丸めを含むので
形の物差しにしない。深度から戻した位置の微分は使わない（D32 の深度の量子化で、遠景の平らな面にも偽の折れ目と差が出る）。
深度は世界座標の範囲・距離・格子の段を引くのと、輪郭（隣との深度の飛び）を外すのにだけ使う。どの視点も地形の画素の 100 % で幾何の法線が読める。

| 量 | 意味 | 重ね画の色 |
|---|---|---|
| 格子の限界 | 高さの格子の 1 升（近景 1 m・castle 2 m・mid 8 m・far 16 m・outer 32 m。`horizon.json` の levels）が 4 画素以上に写る画素の割合。升の中の形は格子からは来ない | 青 |
| LOD の差 | (a) と (b) の幾何の法線の角の差が 8° を超える画素の割合 | 赤 |
| 崖の生成の差 | (b) と (c) の差（同じ測り方） | 緑 |
| 材質の陰影 | (a) の GBuffer の法線（陰影に使う頂点の法線）と幾何の法線の角の差が 15° を超える画素の割合。陰影が形より丸い所 | 黄 |
| 折れ目の密度 | 幾何の法線が 4 画素の間で 20° を超えて曲がる画素の割合（丸いほど小さい）。面の法線なので、三角形の継ぎ目の折れを数える | — |

画面を 3 行 × 4 列の升に分け、升ごとの値と世界座標の範囲（5〜95 百分位）を `<置き場>/shape_cause.json` に書き、
視点ごとの並べた画（上: 写真・(a) の撮影・原因の重ね、下: 3 組の幾何の法線の陰影）を `<置き場>/shape_cause/<視点>.png` に書く。

3 組は同じ Game.exe（`ab0adb16…`、RelWithDebInfo）で撮った（`inputs.json`）。(c) は近景と castle の段の 67 区画を差し替えた（`WASTELAND_CLIFF_DETAIL_OFF swapped=67`）。
3 組とも崖錐の岩を全部置き（`fragments=274965`）、BVH のたどりの列の溢れは 0（`MEGA_CAPACITY bvh_overflow=0`）。

谷床と崖錐の緩い面は格子のまま描かれる。崖の壁は崖の生成で折れ目が増えているが、増えた折れ目は縦の溝で、写真の崖の水平の地層の棚と上端の角は作っていない。
遠くの崖が丸く見えるのは、形（面の法線の折れ目 55〜71 %）より、陰影の頂点の法線が形を均した分（差 15° 超が 22〜32 %）が大きい。

## 形の物差し

後の形の直しの合否に使う、崖の棚・角・外形の量（SCN-WL-SHAPE-MEASURE）。写真の注釈と撮影の深度・幾何の法線を画像の座標で対応づける。

```
python Scripts/Terrain/CompareReference.py --capture <-Aov の撮影> --photos far_01,far_02,cliff_01,cliff_02,ground_02 --shape [--expect <仕様>] [--verify]
```

- 注釈: `Scripts/Terrain/ShapeAnnotations.json`。写真ごと（far_01・far_02・cliff_01・cliff_02・ground_02）に崖の名前を付け、外形は輪郭の多角形、棚は線分、角は点で置く（座標は 16:9 に合わせた写真の絵の割合）。崖は far_01 の Castle Butte・2 本の尖塔・Cedar Mesa の縁（右）、far_02 の Setting Hen Butte・Rooster Butte、cliff_01 の Battleship Rock、cliff_02 の Franklin Butte、ground_02 の Franklin Butte・Rooster Butte。崖ごとの `depth_max_m` は撮影の側の外形を奥の地形から分ける深度の上限で、今の撮影の深度から決めた
- 撮影の側の折れ: 横・縦・2 つの斜めの向きに 3 画素ずつ前後の 2 点で、面の法線の角が 30° 以上か、深度の段か、片方だけが空。深度の段は、外側の 2 点（さらに 3 画素先）から深度の逆数を直線で延ばした予測が、両側とも相手の点の深度の逆数から 5 % 以上外れるもの（斜めに見た平面の深度の勾配は段にしない。外側が地形でない側は使わず、両側とも使えなければ前後の深度の相対の差 5 % で決める）。その向きだけで折れ（直交する向きでは折れない）、折れの線の向きに 10 画素以上続く画素だけを残す。縦の溝は横を横切る折れになるので横の棚の判定に入らず、崖錐の岩の小さな折れも落ちる。輝度は使わない（材質の縞・影・露出で段が作れ、照明の向きで正しい棚にも陰が出ないため）
- 外形: 写真は多角形の列ごとの上の縁、撮影は列ごとに深度 `depth_max_m` 以下の最も上の画素。写真の外形の点から撮影の外形への距離の中央値を「外形の距離」とする
- 位置の対応: 崖ごとに外形の距離の中央値が最小になる平行移動を、幅の ±6 %・高さの ±8 % の内で探す（ground_02 の Rooster Butte は撮影の構図が幅の約 1 割ずれているので注釈で幅の ±12 % に広げた）。棚と角の注釈はその分ずらして撮影に置く
- 位置の許容: 8 画素（1920 幅）。今の撮影で、全部の崖のずらした後の外形の距離の中央値が 7.1 画素（点をまとめた値。崖ごとには 2.8〜13.5 画素）だったので切り上げた。この許容は棚と角の一致の探す幅で、外形の距離の値そのものには掛けない
- 量: 棚の一致（棚の線分のうち、線分に垂直に ±8 画素の内に棚の向きを横切る折れの線がある長さの割合）、角の一致（角の点のうち、半径 8 画素の内に直交する 2 つの向き〔横と縦、または 2 つの斜め〕の折れの線がそれぞれ 3 画素以上ある点の割合）、外形の距離の中央値（ずらす前。ずらした後と、ずらした量も書く）
- 出力: `<出力先>/shape_<写真>.png`（上: 写真と注釈、下: 撮影と折れの線〔赤〕・撮影の外形〔水色〕・ずらした注釈〔緑 = 一致、橙 = 不一致〕）と `shape_metrics.json`。`--expect` の仕様は行ごとに写真・量（`shape_metrics.json` の写真の記録の中の道。`cliff` で崖を選べる）と min・max を持つ（`Scripts/Terrain/PhotoExpect.py`。`--look` も同じ形）。未知の写真の ID・選んだ写真の行が無い仕様・注釈の欠けは落ちる

### 合否の使い方

形の直しの項目は、絶対の基準と前からの改善を分けて合否にする。

- 絶対の基準（`Scripts/Terrain/ExpectSpecs/shape-target.json`）: 担当の写真で、棚の一致 0.6 以上・角の一致 0.5 以上・ずらした後の外形の距離の中央値 8 画素（位置の許容）以下。今は全部の写真で棚（最大 0.57）と角（最大 0.25）が届かない。0.6 は最も細かい LOD の最大 0.59 より上で、LOD を細かくするだけでは届かず、崖の生成に棚を足して初めて届く値。角は点が 2〜7 個なので 0.5 は半分の点
- 前からの改善（`Scripts/Terrain/ExpectSpecs/shape-baseline.json`）: 今の値から悪くならない（棚の一致 −0.03・外形の距離 +1 画素の揺れまで）。直しの項目は担当の写真の行の min を今の値より上げて書く（例: 棚の一致を今の値 + 0.15 以上）
- 外形の距離のずらす前の値は、far_02（48 画素）と ground_02（32 画素）では撮影の構図のずれ（地平の高さと崖の左右の位置）が大半で、形の直しでは変わらない。形の直しの外形の判定はずらした後の値を使う

## 地形の画素の印（撮影の AOV）

形の量（`ShapeCause.py`・`CompareReference.py --shape`）を地形の画素だけで数えるために、撮影の AOV（`CaptureScene.ps1 -Aov`）は `<視点>.aov.terrain_id.pfm` を書く。開発ビルド（Debug・RelWithDebInfo）の撮影だけの機能で、Release には AOV のパスが無い。

- 値: 画素の三角形の材質が地形の面（`MegaTerrainBlend::IsTerrainSurface`。荒野では地形の区画だけが立てる。灰色の材質の地形も含む）なら 1、ほかの物（崖錐の岩・スキャンの崖の塊など）なら 0、空は 0、このフレームに可視バッファの解決が書いていない画素は 255。読む側は 255 を拒む
- 同じフレームの値: 解決は面の法線と同じ画素の書き込みで、印の符号に地形かを載せる（`VisResolve.GeometricNormal` の w = ±フレームの印、負が地形）。AOV のパスは印の絶対値が今のフレームの値と合う画素だけを読むので、同じ起動で視点を替えて資源が使い回されても、前のフレームの値は 255 になり数えられない。`.aov.json` の `terrain_id`・`geometric_normal` にフレームの番号と印を書く
- 検査: `ReferenceCheck.py --aov-terrain-id --engine <-Aov の撮影> --plain <-Aov なしの撮影> --plain2 <-Aov なしを別の起動でもう 1 回撮った撮影> --verify`（`AovTerrainIdCheck.py`）。値が 0・1・255 だけ、描いた画素に 255 が無い、空は 0、面の法線が書かれた画素と印が書かれた画素が一致、フレームの番号と印が深度・面の法線の記録と同じ、同じ起動の 2 視点のフレームの番号と印が違う、`-Aov` の有無の PNG の差が 1 段以内の画素の割合が `-Aov` なしどうしの割合 − 0.002 以上。印を PNG に重ねた画（地形 = 緑・ほかの物 = 橙・書かれていない画素 = 赤紫）を `terrain_id_<視点>.png` に書く
- 通常の描画に影響しないことを、固定の割合でなく起動ごとの揺れと比べる理由: 同じ起動引数の撮影でも、起動ごとにストリーミングの間合いと RT・GI の時間方向の積み重ねが違い、崖錐の岩の面の影が揺れる。同じ Game.exe で、ある `-Aov` の起動は ref_cliff_01 で `-Aov` なしの 2 回の起動と 0.9804 しか合わなかった（差の画素の 85 % が岩の面で、暗い側に寄る）が、もう 1 回の `-Aov` の起動は `-Aov` なしと 0.99987、`-Aov` なしどうしは 0.99985 で揃った。岩の配置の書き出し（`occlusion_props.placements.csv`）は起動どうしで同じ

| 視点 | フレーム（印） | 地形 | ほかの物 | 空 | 書かれていない描いた画素 | `-Aov` の有無の差が 1 段以内 | `-Aov` なしどうし（下限） |
|---|---|---|---|---|---|---|---|

## 既知の限界

- 折れ目と差の画素は面の法線から測るので、1 画素に複数の三角形が入る遠景（最も細かい LOD の 0.5 m/画素より遠い崖）では、画素が拾う三角形で値が揺れる。値は 3 組の比べにだけ使う（絶対の目標にしない）。
- 面の法線は可視バッファで解決した画素だけが持つ（MegaGeometry の地形・岩）。ラスタの GBuffer で描く物は読めない値（-1）になる。荒野の 5 視点の地形の画素はすべて読めた。
- 遠景の格子の段の量は、崖の生成と材質の陰影から分けて測っていない（段を細かくした撮影が無い）。
- 崖錐の岩（崖錐の散布と崖のスキャン）は 3 組とも通常の段で同じに置いたので、岩の形は比べの外。最も細かい LOD で岩も段 0 で描くと BVH のたどりの列が溢れて地形が抜ける。
- 形の物差しの角は写真ごとに 2〜7 点しかなく、角の一致は 1 点で 0.14〜0.5 動く。角の判定は直交する 2 つの向きの折れの線が近くにあれば通るので、縦の溝と横の折れが交わる所でも通る（角の丸さの量ではなく、角の近くに 2 つの向きの折れがあるかの量）
- 形の物差しの位置の対応は外形だけで平行移動を決めるので、外形の形が写真と違う崖では別の所に合うことがある（far_01 の Cedar Mesa の縁は 127 画素右にずれて合い、棚と角の置き場所が粗い。far_02 の Setting Hen Butte はずらした後も 13.5 画素で、大きさと肩の高さが写真と違う）。拡大と縮小は探さない
- 形の物差しの棚の一致は、崖錐の岩の縁や地層の材質の継ぎ目でも続いた折れの線なら一致に数える。灰色の材質で撮った撮影を測る前提で、岩を外した撮影とは比べていない
