# 地表の材質の法線と粗さを Blender で再現し、照明の無い値を照合する

荒野の正解の絵（SCN-WLR-*）で、地形の地表の材質の法線と粗さの経路を、アルベドの再現（`WastelandMaterialAlbedo.md`）と同じ
Blender の Cycles の OSL のシェーダーへ足し、エンジンの GBuffer の生の法線と粗さ（SCN-WLR-BARE-AOV の書き出し）と照明の無い値で
比べた記録。判定日: 2026-10-19。ブランチ `feature/scene-launcher`。タスク SCN-WLR-MATERIAL-NORMAL。

## 道具

アルベドの再現と同じ道具に、法線と粗さを足した。

| 何 | どこ | 足したこと |
|---|---|---|
| `Scripts/Terrain/TerrainMaterialReference.py` | | 3 層の法線マップと ORM の粗さ（G）の全ミップの段を作る。法線はクックの `BuildNormalMips` と同じく、8 bit を −1〜1 へ戻したベクトルを正規化せずに箱で足し、1 回だけ正規化して 8 bit へ丸める（段 0 は元の 8 bit のまま）。粗さは元の画像（`WastelandTerrain.json` の `orm_roughness`）から 8 bit の平均で作る。BC5 の 2 チャンネルの印（`NORMAL_TWO_CHANNEL`）を OSL の定数へ出す |
| `Scripts/Terrain/TerrainAlbedo.osl` | | `ShadeTerrainLayers` の法線の傾きと粗さの経路、`ComputeTerrainStrata` の法線の傾き（地層の張り出しと葉理の凹凸）を写した。出力は傾きを足した法線（`ShadedNormal`）、傾きを足す前の法線（`BaseNormal`）、粗さ（R: 足した後、G: 足す前、B: 足した分散） |
| `Scripts/Terrain/BlenderReference.py --normal` | Blender 5.2.2 をヘッドレスで起動 | 視点ごとに、エンジンのカメラで書き出しの地形を、OSL の出力のパスごとに放射させて 1 サンプルで描く。`<撮影>/normal/` に 2 通りの法線・粗さ・頂点の法線・被覆の PFM と `inputs.json` を書く。三角形の多い ref_cliff_01 は画面を縦 4 列に分けて描いて繋ぐ |
| `Scripts/Terrain/ReferenceCheck.py --normal` | | アルベドと同じ入力の検査（撮影の起動引数・ログ・常駐、台本・OSL・値の表・ミップの段・メッシュのハッシュ）の後、領域ごとに法線のなす角と粗さの平均を照合し、見比べの画像 `normal_<視点>.png` を書く |

## 再現した処理

- 法線マップの空間と向き: 接空間の法線。BC5 で張られた R・G を −1〜1 の X・Y とし、Z を単位長から戻す（`DecodePbrTangentNormal`）。
  向きは DirectX（緑が画像の下 = V が増える向き）で、V が下へ増える Vulkan の UV と同じ向きなので反転しない
- 傾きの載せ方: 接空間の法線を傾き（X / Z、Y / Z。Z は 0.1 で下を切る）へ直し、距離の段の回転を戻してから、投影ごとの面の軸
  （投影の U・V の軸を幾何の法線の接平面へ落として正規化したもの。`TerrainTangentAxis`）へ載せる
- 三方向の投影の混ぜ: 投影の重み（`ComputeTerrainTriplanarWeights`）で 3 つの投影の傾きを足す。距離の 2 つの段の間も同じ重みで混ぜる
- 強さ: 模様の 1 枚が画面で縮む遠くで、傾きを 0 へ落とす（1 枚あたりの画素から smoothstep で決める `normalFade`）
- 岩肌: 地層の張り出しと交差層理の葉理の凹凸の傾きを足す
- 層の混ぜ: 幾何の法線（遠くでは遠景の地図の法線へ移したもの）に、3 層の傾きを高さの混ぜの重みで足して正規化する
- 粗さ: ORM の G を層ごとに投影の重みで混ぜ、ワニスで下げる（× 0.85 まで）。傾きを落とした割合（1 − normalFade²）× 層の傾きの
  分散（`WastelandRoutine.cpp` の `kDetailSlopeVariance`。シェーダーへは `farMix.yzw` で渡る）を層の重みで混ぜ、α²（= 粗さ⁴）へ足す
- 標本: アルベドと同じ異方性の標本（段の偏り +1）で、法線と粗さの段を引く

## 再現できない処理とその扱い

| 処理 | 扱い | 影響（測った値） |
|---|---|---|
| BC5（法線）・BC7（ORM）の圧縮 | 再現しない（Blender は圧縮前の 8 bit の段を引く） | 法線の角の中央値の上限 2° と、粗さの平均の差の許容 0.02 に含める |
| GPU の異方性の標本の実装 | アルベドで決めた段の偏り +1 をそのまま使う（法線と粗さでは決め直していない） | 近景の地面の角の中央値 1.60°（傾きを足さない対照は 4.02°） |
| エンジンの GBuffer の書き出しの量子化 | 再現しない | 粗さは 8 bit（1/255） |

## 照合の測り方

- 撮影と領域: アルベドの照合と同じ（共通の照明・地形だけ・最細の LOD、1920×1080、RelWithDebInfo、`-Aov`。輪郭から 3 画素を除き、
  Blender の頂点の法線と深度で平らな地面の近景・中景・遠景、斜面、崖に分ける。5000 画素未満の領域は判定しない）
- 法線: 画素ごとにエンジンの法線と Blender の傾きを足した法線のなす角を測り、領域ごとに中央値 ≤ 2°・95 百分位 ≤ 8°。
  上限は、差の元（異方性の標本の実装の残りと BC5 の圧縮）が画素ごとの傾きに 1〜3° の標準偏差を作ると見積もって決めた
  （2 次元の大きさの中央値は標準偏差の約 1.2 倍、95 百分位は約 2.4 倍）
- 法線を判定する画素: 次の 2 つは記録だけにして判定から外す。どちらも比べる値を使わず、深度と Blender の幾何だけで決める
  - カメラから 3 km より先: エンジンの描く地形の形が書き出しの LOD 0 と食い違う（ref_ground_01 で Blender の深度との相対差の
    95 百分位が 1〜3 km の 2.3e-4 から 3〜8 km で 1.6e-3 へ増える）。幾何の法線の差が材質の差を覆う
  - 幾何が画素で分解できていない画素: Blender の頂点の法線と上下左右の隣の画素の頂点の法線のなす角の最大が 4° 以上の画素。
    崖の細部の三角形が画素より小さい所では、画素の中のどの三角形を拾うかで幾何の法線が十数度変わる（ref_cliff_01 の崖で
    外れた画素の頂点の法線の隣との差の中央値 17°、エンジンと頂点の法線の差 14°、Blender の材質の傾き 1.3°）
- 粗さ: 領域ごとの平均の差（Blender − エンジン）の絶対値 ≤ 0.02。粗さは幾何に依らないので全画素で判定する
- 対照: 法線は傾きを足す前の法線（`BaseNormal`）、粗さは遠くで落とした傾きの分を足す前の粗さで同じ値を測る。対照の法線の
  95 百分位が 8° を超える領域・対照の粗さの平均の差が 0.02 を超える領域を「比べ方が見分けられる領域」とし、視点ごとに法線と
  粗さのそれぞれで 1 つ以上要る

## 既知の限界

- 崖の法線は、幾何が画素で分解できている 17 % の画素だけで判定している。残りは幾何の拾い方の差が材質の差を覆う
- 中景より遠くの地面と斜面では傾きが 0 へ落ちているので、法線の照合が確かめているのは幾何の法線（と遠景の地図の法線）の一致で、
  傾きの再現を見分けているのは ref_ground_01 の近景と ref_cliff_01 の崖だけ
- BC5・BC7 の圧縮と、GPU の異方性の標本の実装は再現していない（法線と粗さでは段の偏りを決め直していない）

## 描き直しの手順

```
# エンジン（照合の読む撮影）
powershell -Command "& ./Scripts/CaptureScene.ps1 -Scene wasteland -OutDir .harness/runs/scene-capture/SCN-WLR-MATERIAL-NORMAL `
  -Views ref_cliff_01,ref_ground_01 -Configuration RelWithDebInfo -Build -Width 1920 -Height 1080 -Hdr -Aov -LaunchPerView `
  -GameArgs @('--wasteland-common-light','--wasteland-hide=all','--wasteland-finest-lod')"
# Blender（値の表・ミップの段・OSL を作り、2 視点を描く。ref_cliff_01 は 4 列で約 5 分、ref_ground_01 は約 1 分）
python Scripts/Terrain/BlenderReference.py --normal --mesh .harness/runs/scene-capture/SCN-WLR-BLENDER-TERRAIN-mesh `
  --capture .harness/runs/scene-capture/SCN-WLR-MATERIAL-NORMAL
# 照合
python Scripts/Terrain/ReferenceCheck.py --normal --capture .harness/runs/scene-capture/SCN-WLR-MATERIAL-NORMAL --verify
```

OSL の本体はアルベドと共有なので、OSL・台本・値の表を変えたときはアルベドの照合（`WastelandMaterialAlbedo.md` の手順）も描き直す。
