# 荒野の遠景のぼけを静止の撮影で切り分ける

荒野の遠くの崖がぼけて見える原因を、条件を 1 つずつ変えた静止の撮影で切り分けた記録。判定日: 2026-10-19（同じ日にエンジンの実装の署名つきの記録の形で全 10 組を撮り直した。下の「撮り直し」）。
ブランチ `feature/scene-launcher`。タスク SCN-WLR-FAR-BLUR-STATIC・SCN-WLR-FAR-BLUR-LOD。既定の見た目は変えていない（条件はすべて開発ビルドの起動引数）。

## 測り方

- 正解: 同じ視点を 2 倍の解像度（3840×2160）・AA なしで撮り、線形の光で 2×2 を平均して 1920×1080 へ縮めた画（超標本化）。
- ジオメトリの常駐: 比べる組（正解を含む）は VRAM の予算のジオメトリの取り分を 9 に広げて撮る（`--vram-geometry-share=9`。
  描くものは変えない）。既定の取り分 1 では、1920×1080 でも 2 視点の作業集合がページの目標に収まらず、追い出しと読み直しが
  続いたまま撮れてしまう（下の「撮影の確かめ」）。条件の効きは、取り分だけを広げた組（resident）との差で数え、
  既定の取り分そのものの効きは base（取り分 1）と resident の差で数える。
- 範囲: 正解の深度が 1000 m より奥の地表（2×2 のすべてが奥）を遠景、そのうち法線の |y| が 0.8 未満の面を崖とする。
  範囲の外（空・近景）から 2σ 画素以内は数えない（空との輪郭の強い縁が帯域に漏れるため）。
- 帯域: 表示の値（PNG の符号化のまま）の輝度を、隣り合うガウスの差 G(σk) − G(σk+1)（σ = 0・1・2・4・8 画素）の 4 帯域に分ける。
- 帯域ごとに、条件の帯域を正解の帯域へ射影した利得 g（細部の残り。1 − g が細部の欠け）と、射影の残り（正解に無い成分）の
  量 ÷ 正解の量（エイリアス）を求める。エイリアスは鮮明さに数えない。細かい 2 帯域（σ 0〜1・1〜2）を正解の量で重み付けて
  まとめた値を表に載せる。
- 較正: 正解を σ 0.8 でぼかした画は細部の欠けに（帯域 0 の欠け 0.3 以上・エイリアス 0.1 以下。ぼかしは帯域の中の形も少し
  変えるので 0.05 前後の残りが出る）、正解に白色雑音を足した画はエイリアスに（帯域 0 の残り 1 ± 0.05・エイリアス 0.3 以上）
  数えられることを、視点ごとに確かめる。
- 撮影の確かめ: 組ごとに、条件を替える起動引数が約束どおりで、Game のログに差し替えの印があり（既定の組には無く）、
  全組が同じ入力のハッシュと同じ Game.exe（撮影が `inputs.json` に書いた実行ファイルの中身の SHA-256）で撮れていること
  （入力のハッシュは撮影の後のソースから作るので、実際に走ったコードの一致は実行ファイルのハッシュで照らす）。荒野は仮想テクスチャを使わない（`VRAM_POOLS` の `vt_used_mb` がどの行も 0）ので、
  VT の常駐の待ちは要らないことをログで確かめる。
- ジオメトリの常駐の確かめ: `GEOMETRY_PAGES` の行は、常駐・進行中の各段（要求・読み込み・書き込み待ち・書き込み）・追い出しの
  数のどれかが変わると出る（落ち着き待ちの間は毎フレーム）。base 以外の組は、視点ごとに保存の前の最後の行の進行中が
  すべて 0 で、最後の落ち着きの基準（`CAPTURE_VIEWS ... settle baseline`）から保存までに追い出しの数が変わっていないことを求める。
  base は既定の取り分のまま撮るので求めず、状態を記録する。

検査: `python Scripts/Terrain/ReferenceCheck.py --blur-static --capture .harness/runs/scene-capture/SCN-WLR-FAR-BLUR-STATIC --verify`。
結果は `blur_static_check.json`、切り出しの並びは `blur_<視点>.png`。

## 撮り直し（2026-10-19）

全 10 組を、エンジンの実装の署名（`inputs.json` の `engine_impl`）つきの記録の形で、同じ RelWithDebInfo の Game.exe
（SHA-256 e2e2e3d9…、撮影の始めと終わりで同じ）で撮り直した。上の表はこの撮影の値。前の撮影（コミット 6ba6e8dd、
Game.exe 4deec25e…）からの変化:

- 正解と比べる 8 組の細部の欠け・エイリアスの差は 0.017 以下。ref_far_01 は全組で欠けが 0.003〜0.007 減り、
  エイリアスが aa-taa のほかで 0.003〜0.017 増えた。ref_cliff_02 は欠けの差が 0.006 以下、エイリアスは finest-lod の崖が
  0.012 増・scale-075 が 0.014〜0.015 減のほかは 0.005 以下。
  条件の効き（resident との差）は 0.008 以下しか動かず、原因の順位は変わらない。
- 霞の効きは大きく動いた: haze-off の ref_far_01 は欠け −0.017 → 0.035、エイリアス 1.225 → 1.101、
  霞が細部の見えを下げる量は 0.74 → 0.78〜0.79（ref_cliff_02 は 0.81〜0.83 → 0.79〜0.81）。
- 主な原因は、2 つの撮影の間で荒野の昼のグレーディングを中立にしたこと（コントラスト 1.35・彩度 1.2・色温度 0.05 → 1・1・0、
  `WastelandGradeNeutral.md`）。帯域は表示の値（PNG）で測るので、コントラストの曲線が変わると帯域の量と霞あり・なしの比が変わる。
  ほかに Game の変更は夜の集落の追加（`WastelandLayout`）・検証レイヤーの起動引数・Rendering3DTest のカメラ台本で、
  正解の常駐のページは 7113・12969 → 7107・12963（−6）と小さい。
- base（取り分 1）は前と同じく常駐が頭打ちのまま撮れ、追い出しの数が撮影の時刻で変わる（ref_far_01 462 → 827）が、
  resident との差は崖の平均で 0.003 以内、前と同じく ref_cliff_02 の遠景にだけ差が出る。

## 原因の順位

条件の効きは 2 視点の崖の平均で、resident との差（細部の欠け / エイリアス）。

1. **画素あたりの標本の不足（エイリアス）**: ページが常駐しきった resident でも、エイリアスが正解の量の 0.64〜0.73 倍あり、
   細部の欠け 0.22〜0.28 より大きい。内部解像度を 0.75 に下げると欠けが +0.282 増え、2 倍で撮った正解との差の大半は
   1 画素 1 標本の描き方そのものから来る。遠景の「ぼけ」に見えるものの多くは、細い筋が標本の間に落ちて途切れる・階段になることによる。
2. **霞**: 遠景の帯域の量を全帯域でほぼ一様に 0.78〜0.81 倍に下げる（コントラストの低下。帯域の形は変えない）。
   空気遠近の散乱光が正解の 0.56〜0.90 倍である（SCN-WLR-ATMOS-REF）ことと合わせ、霞の量そのものは過大ではないが、
   コントラストを落とす分だけ鮮明さの印象を下げる。
3. **既定のジオメトリの取り分（常駐の不足）**: base は作業集合の 78〜86 % しか常駐せず、ref_cliff_02 の遠景（崖の奥の平地）で
   欠け +0.046・エイリアス +0.072、粗い帯域の残りが 0.91・0.96 → 0.84・0.88 に下がる（足りないページの代わりに粗い段が描かれる）。
   崖の面（崖の平均 +0.002 / +0.003）と ref_far_01 には差が出ない。追い出しが撮影の時刻で変わるので、撮るたびに揺れる。
4. **既定の LOD の選び方（細部の欠け）**: 最も細かい段に固定すると、細部の欠けが −0.078 減る（σ 0〜1 の残りが ref_far_01 で
   0.73 → 0.84、ref_cliff_02 で 0.68 → 0.74）代わりに、エイリアスが +0.271 増え正解の量の 0.83〜1.04 倍になる。既定の LOD は
   画素より細かい形を落として欠けを作る一方で、エイリアスを抑えている。欠けの源としては 1 位の標本の不足（内部解像度 0.75 で +0.282）
   より小さく、LOD を細かくするだけでは標本の不足のエイリアスが増えて鮮明には見えない。
5. **TAA**: エイリアスを半分（−0.320）に減らす代わりに細部の欠けを +0.117 増やす（σ 0〜1 の残りが 0.73 → 0.56）。静止でこの欠けなので、
   履歴の再投影の補間か近傍の色の押さえ込みが細部を削っている（動きの分は SCN-WLR-FAR-BLUR-MOTION）。
6. **効かないもの**: FXAA の有無（欠け −0.006・エイリアス +0.043）、地形の材質のミップの偏り −1（−0.003・−0.005）、異方性フィルタ（+0.000・−0.001）。
   遠景の崖の細部は材質のテクスチャではなく、ジオメトリと陰影の側にある。

## 直す案

- 遠景の標本を増やす: TAA の静止の収束を正解に近づける。今の TAA は履歴を Catmull-Rom で読み、分散の箱（γ 1.0）でクリップし、
  Halton(2,3) の 8 つのジッタを回し、現在の色を 0.1 混ぜる（`Rendering/TemporalAA.h`）ので、補間とジッタの列ではなく、箱の幅・混ぜる割合・
  書き戻しのシャープ化（0.25）の釣り合いを見直す。静止で欠けが resident 以下・エイリアスが TAA 並みになることを同じ測り方で確かめる。
  動いている間の分は `WastelandFarBlurMotion.md`。
- 余力があれば遠景だけ標本を増やす（崖の稜線と急な面の画素だけ 2 標本にする、など）か、解像度を上げる経路（DLAA 相当）を比べる。
- ジオメトリのページの目標を、荒野の 1920×1080 の作業集合（ref_cliff_02 で 8120 ページ・897 MB）が収まる大きさにする（済み。下の「既定のジオメトリの目標」）。
  収まらないときは追い出しと読み直しを繰り返さず、粗い段で止めて落ち着かせる（SCN-WL-GEOM-LOWVRAM）。
- 材質のミップの偏りと異方性は変えない（効果が測れない）。霞の量は SCN-WLR-ATMOS-REF の差の扱いで決める。
- LOD の閾値は標本を増やす経路と組にして見直す（LOD を細かくすると欠けは −0.078 減るがエイリアスが +0.271 増える。
  標本を増やした後なら、細かい段の形がエイリアスでなく細部として残る）。

## 既定のジオメトリの目標（SCN-WL-GEOM-BUDGET、2026-10-21）

既定の取り分（VT 3 : ジオメトリ 1）は変えず、ジオメトリの目標を読み込んだメッシュの作業集合の求めから決める。
求め = メッシュの区画とページの置き場の見込みの合計（`MegaGeometryResourceStore::GetCommittedBytes`）＋ 塊 1 つ分（1 GB）。
取り分の目標が求めに届かないときは求めを目標にし（割り振れる量まで）、残りを VT へ分ける（`VideoMemoryBudgetManager::SetPoolDemand`、
`RenderResources::PollVideoMemoryBudget`）。ページはメッシュと同じ塊にしか置けないので、前は目標で新しい塊が切り詰められ、
置き場の埋まった塊のメッシュのページが書けずに残っていた（`upload_blocked`）。

比べた 2 つは同じ HEAD（cb65a889）で、前は求めを渡す 1 行だけを一時的に 0 にしたビルド。どちらも 1920×1080・RelWithDebInfo・
既定の取り分。撮った時点の `GEOMETRY_PAGES` と `VRAM_POOLS`・`VRAM_LEDGER geometry_pool`:

| | ref_far_01 の常駐 | ref_cliff_02 の常駐 | ジオメトリの目標 | 塊の確保 | VT の目標 |
|---|---|---|---|---|---|
| 前（求めなし） | 3441・書き込み待ち 28 | 7128（788 MB）・書き込み待ち 21・置き場待ち 984 | 2385 MB | 4 塊 2741 MB | 7155 MB |
| 後（求めあり） | 4043・進行中 0 | 8121（897 MB）・進行中 0・置き場待ち 0 | 4164 MB（= 求め） | 4 塊 4036 MB | 5375 MB |
| resident（取り分 9） | 4043〜4044 | 8120〜8122 | | | |

上限 15280 MB・プール以外 5116 MB・VSM 623 MB はどちらも同じ。どちらも追い出しは 0。荒野は VT を使わない（`vt_used_mb` 0）ので、
VT の目標が 1780 MB 減っても描画は変わらない。塊の確保は 1295 MB 増える（メッシュの区画とページの置き場が 4 つの塊へ広がる分）。

検査（`--blur-static --expect geom-budget.json`。ref2x・base・resident を後の同じ Game.exe で撮り直した）: base − resident は
細部の欠け −0.0011〜+0.0004、エイリアス −0.0021〜−0.0006 で、8 行とも ±0.01 以内（前は ref_cliff_02 の遠景で +0.042 / +0.069）。

|---|---|---|
| 前 | 9.59 / 10.50 ms | 6.25 / 7.06 ms |

予算が足りないとき（ほかのアプリが VRAM を使う）は、求めが割り振れる量で頭打ちになり VT の目標が 0 まで下がりうる。
そのときの落ち着かせ方は SCN-WL-GEOM-LOWVRAM で扱う。
