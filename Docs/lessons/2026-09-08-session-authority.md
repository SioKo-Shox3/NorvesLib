# 再開時の規則と基点

古い計画に担当モデルや実装委譲の手順が書かれていても、再開時のAGENTS.mdを優先する。技術仕様と運転手順を分け、更新された運転規則を古い計画から戻さない。

再開時は `git status`、`git log`、現在のファイルhashを読む。作業中に保存コミットが増えた場合は、検証snapshotとのbyte一致を調べ、実hashと実subjectを進捗へ記録する。記録を合わせるために既存コミットを改変したり、見ていないstage状態を合格と書いたりしない。

後続の入口は、記録された描画コミットとsource同一性を確認する。進捗文書だけのコミットと描画変更を混同しない。
