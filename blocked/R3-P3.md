# R3-P3 停止記録 — 2026-09-20

## 決めたいこと
`shadowed-shafts` GPU検証で使う高さフォグを有効化するGameThread→RenderThread設定経路を、このタスクの許可パス外へ追加できるか。

## 確認した事実

- `VolumetricFogParameters::bEnabled` の既定値は `false` で、`MakeDefaultVolumetricFogParameters()` は既定値を返す。
- `VolumetricsPass::Declare()` は `SnapshotScene->VolumetricFog.bEnabled` が false の場合にパスを宣言しない。
- `RenderWorld` と `RenderingCoordinator` にある環境設定APIは `SetSkyAtmosphere` までで、volumetric fog setter はない。FramePacketの `Scene` は RenderWorld/Coordinator が構築する。
- 指定された fixture はカメラ・遮蔽物・ライトを設定できるが、`FramePacket.Scene.VolumetricFog` を設定できない。したがってfogが無効のままでは指定GPU captureから散乱の遮蔽差を検証できない。
- 許可パスには `RenderWorld.h/.cpp` と `RenderingCoordinator.h` が含まれない。パケットの公開経路を正しく追加するにはそれらの変更が必要になる。
- 初回ベースラインは指定4ターゲットbuild成功、契約CTest 3/3成功。GPU smokeは未実装引数 `--r3-scenario=shadowed-shafts` を拒否して exit 1。最終検証ログはまだ作成していない。

## 選択肢

1. **推奨: 設定APIを許可パスへ追加する。** `RenderWorld` と `RenderingCoordinator` に高さフォグ設定を追加し、GameThreadの設定値を次のFramePacketへコピーする。GPU fixtureからこのAPIを呼び、既定値と無効時の契約を保ちながら実シーンを検証できる。許可パスの拡張が必要。
2. **許可パス内でテスト専用の暗黙シグナルを使う。** カメラの予約値などから RenderThread 側でfogを強制する。公開APIを増やさずに済むが、検証用条件が描画処理へ漏れ、FramePacketの明示的スナップショット契約を弱めるため推奨しない。

## 2026-09-20 再確認

- 指定4ターゲットの Debug build は成功した。
- 指定3件の契約 CTest は `100% tests passed, 0 tests failed out of 3` で終了した。
- 指定GPU captureは `--r3-scenario=shadowed-shafts` を渡したが、現在の capture test にR3シナリオ引数がなく、終了コード1で拒否された。R3用fixtureの準備関数はあるが、capture handlerから呼び出されていない。
- `RenderWorld` / `RenderingCoordinator` の公開設定経路は `SetSkyAtmosphere` のみ。`SceneProxy` にはフォグ値があるものの、GameThreadの設定値を次の `FramePacket.Scene.VolumetricFog` へ渡すAPIがない。`VolumetricsPass` は無効なfog snapshotではパスを宣言しないため、GPU captureでCSM散乱を観測できない。
- したがって現在の許可パスだけではR3-P3の `done-when` と全verifyを満たせない。`TASKS.md` は `todo` のままにし、最終verifyログは作成していない。

## 決めたいこと

R3-P3の許可パスに以下を追加し、fog設定をGameThreadから次のFramePacketへ渡すAPIを実装してよいか。

- `Library/Core/Public/Rendering/RenderWorld.h`
- `Library/Core/Private/Rendering/RenderWorld.cpp`
- `Library/Core/Public/Rendering/RenderingCoordinator.h`

SceneProxyには既にsanitizedなフォグ設定を受け取るsetterがあり、新しい所有権経路やRHI資源を足す必要はない。上記3ファイルを許可すれば、既定値を保った明示的なsnapshot経路を設け、capture fixtureでのみfogを有効化できる。

### 選択肢

1. **推奨: 上記3パスをR3-P3へ追加する。** GameThread設定をCoordinatorが保持し、FramePacket作成時にSceneProxyへコピーする。fog無効時の既定動作と既存の描画契約を維持したまま、指定GPUシナリオを検証できる。
2. **現行パスのまま進める。** カメラ値などの暗黙条件からRenderThreadでfogを強制する。パス追加は不要だが、テスト専用条件が描画処理へ漏れてsnapshot契約を弱めるため推奨しない。

推奨は選択肢1。許可パスの拡張が決まるまで `TASKS.md` の R3-P3 は `todo` のままとする。
