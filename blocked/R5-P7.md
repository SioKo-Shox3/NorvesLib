# R5-P7 — BLOCKED

## 停止理由

独立レビューでRT descriptorのstage visibilityがblockingとして指摘された。`VulkanRayTracingPipeline` は `RayTracingPipelineDesc.descriptorSetLayouts` を `VulkanDescriptorSetLayout` に渡すが、`VulkanDescriptorSet.cpp` の `ToVkShaderStageFlags` はRT stageを変換せず、RT専用bindingの `stageFlags` が空になる。RT shaderからbindingを参照できない状態でpipeline作成が成功する。

この修正対象は今回のR5-P7 `paths:` に含まれない。指定範囲を越えずにblocking指摘を解消できないため停止する。

## 確認できた作業

- 指定Debug buildは終了コード0。ログは `.harness/runs/20260920-174410/verify-R5-P7-1.txt`。
- 専用CTestは1/1 passed。ログは `.harness/runs/20260920-174410/verify-R5-P7-2.txt`。
- shader groupのdescriptor、Vulkan pipeline、SBTの生成、無効group構成の拒否を実装し、GPUテストでgroup handleとSBT regionを照合した。
- `TASKS.md` のR5-P7はblocking指摘の解決まで `blocked` とする。

## 決めたいこと

R5-P7でRT descriptorのstage visibilityまで扱うには `Library/Core/Private/RHI/Vulkan/VulkanDescriptorSet.cpp` の変更が必要だが、現在の許可パス外である。R5-P8のTLAS/output bindingもこの変換を使う。

- 選択肢1: R5-P7の許可パスに `VulkanDescriptorSet.cpp` を加え、6つのRT stage写像とRT-only bindingのpipeline作成検証を追加する。今回の変更範囲は広がるが、R5-P8のdescriptor bindingへ進める。
- 選択肢2: R5-P7はshader groupとSBTの完了条件だけで受け入れ、descriptor visibilityを別タスクへ分けてR5-P8より前に実施する。現在のパス制約は保てるが、タスク一覧とR5-P8の開始条件を更新する必要がある。
- 推奨: 選択肢1。RT pipeline descriptorにdescriptor set layoutが含まれ、stage flagsの空落ちは使えないlayoutを成功扱いするため、P7で修正・検証するのが安全。

## 再開条件

許可パスの範囲を選択肢1または2に合わせて確定してから再開する。選択肢1ではRT stage flag写像とRT-only descriptor bindingの回帰を追加し、R5-P7の指定build/CTestと独立評価を再実行する。
